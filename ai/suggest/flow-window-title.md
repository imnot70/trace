# 心流模式下窗口标题显示笔记路径

> 2026-09-30 用户提案（历史导航复验时提出）。**状态：✅ 2026-09-30 已立项实施** → [requirements/2026-09-30_preview-batch/](../requirements/2026-09-30_preview-batch/preview-batch.md)（FR-2.10.7；D4 拍板为全模式跟随，非仅心流）。

## 需求（用户原述）

尝试将心流模式下的窗口标题从「Trace 笔迹」改成笔记的文件路径或在库中的路径。

## 动机

心流模式下应用内顶栏整体隐藏，用户看不到「当前在写哪一篇」；任务栏 / 窗口切换器（Alt+Tab / Dock）里所有窗口都显示「Trace 笔迹」，多笔记并行写作时无法辨认。把窗口标题让给笔记路径可恢复这一信息，代价为零（心流下标题栏本来就只有系统框）。

## 现状（2026-09-30 核实）

- 窗口标题固定「Trace 笔迹」，主进程创建窗口时设置，此后无动态更新逻辑；
- 编辑器侧当前笔记信息现成（`editor.current`：库名 / 路径 / 显示名）；
- 用户建议两个形态：文件名（`随笔.md`）或库内路径（`测试库 / 随笔.md`），与编辑卡面包屑风格一致。

## 立项时拍板的点

1. **范围**：仅心流模式变换标题（用户原案），还是常规模式也跟随（标题 = `笔记名 - Trace 笔迹`，桌面应用惯例）？后者信息更全但要确认用户接受默认标题变化；
2. **格式**：`库名 / 路径` / `笔记名 — Trace 笔迹` / 纯路径；脏状态（未保存）是否加标记（`•`）；
3. **实现**：渲染端 watch `editor.current` + `app.flowMode` → IPC `win.setTitle`（Electron 原生能力，零新服务）；退出心流恢复默认标题；
4. **其他视图**（网格 / 设置 / 回收站）标题是否区分（如「设置 - Trace 笔迹」）——可顺手做或明确不做。

**预估**：★，0.5 天内（含边界：无笔记时恢复默认、多窗口场景不存在）。
