# 双链悬浮预览（点击 / Alt+Enter 不切走）

> 2026-09-30 用户提案（P3 复验讨论中提出）。**状态：✅ 2026-09-30 已立项实施** → [requirements/2026-09-30_preview-batch/](../requirements/2026-09-30_preview-batch/preview-batch.md)（FR-2.4.27；D1 修订为分场景——所见即所得单击保留编辑入口，预览走 Alt+点击 / Alt+Enter）。动机：写作中点击引用多半是想「看一眼」目标笔记，而现状直接跳转切走（Trace 无多窗口 / 标签，切回靠常用或返回），打断写作动线；心流模式下代价最大。

## 需求（用户原述）

- 鼠标点击引用的笔记链接 → 打开悬浮预览，而不是直接跳转到对应笔记；
- 光标在引用的笔记链接上按 `Alt+Enter` → 打开悬浮预览（同上）。

## 现状（2026-09-30 核实）

- 双链点击（预览分栏 / 所见即所得 widget / 编辑器 Ctrl+Click）共用 `openWikilinkByName`：解析 → **直接打开目标笔记**（断链提示 / 多候选消歧弹层沿用）；
- 悬浮预览管线已完备且多入口复用（`[[` 补全 Alt+Enter、搜索框 Alt+Enter、快速引用面板）：`app.requestNotePreview` 握手 → EditorView 消费——含「别的笔记」预览不与编辑器滚动同步、跨库萤光边框、预览卡「插入引用 / 打开笔记」按钮等成熟能力，**本提案成本主要在入口接线**；
- 待核：光标在双链上（`[[` 补全未活动）按 `Alt+Enter` 的现有行为（预计无动作）——实现时核实并定义。

## 方案要点（立项时拍板）

| 决策点 | 候选 | 备注 |
| --- | --- | --- |
| 单击语义 | ① 单击 = 悬浮预览（推荐）；② 保持跳转 + 增设预览修饰键 | ① 改变习惯，但预览卡有「打开笔记」按钮兜底跳转（v0.3.6 起）；② 保守但可发现性差 |
| 直接跳转出口 | Ctrl+Click 保留直接跳转（或与单击语义互换）；预览卡「打开笔记」按钮 | 必须保留至少一条直达路，防「只能看不能去」 |
| Alt+Enter | 光标在双链上（补全未活动）→ 悬浮预览该笔记 | 与补全态（预览候选）/ 搜索框（预览结果）的 Alt+Enter 上下文互斥，不冲突；光标不在双链上时行为不变 |
| 断链 / 多候选 | 断链维持提示不动；多候选消歧弹层沿用（预览哪篇待定：首篇 / 弹层选择后预览） | — |
| 范围 | 预览分栏双链、所见即所得 widget、源码模式 Ctrl+Click 三处逐一确认 | — |
