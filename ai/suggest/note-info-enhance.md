# 笔记「信息」弹窗内容增强建议

> 2026-10-10 用户咨询：「信息」弹窗目前只有创建时间 / 最后修改，是否应加入笔记标签、所属库的 git 仓库等。**同日已立项实施（P0 + P1，决策 D1–D4 拍板）→ [requirements/2026-10-10_note-info-enhance/](../requirements/2026-10-10_note-info-enhance/note-info-enhance.md)（FR-2.6.6 扩展）**，本文保留为思路存档（P2 项与数据源盘点仍有效）。

## 现状

- 两个入口共用同一实现：侧栏树行（`VaultNode.vue`）与网格卡片（`NoteGridView.vue`），均为 `ElMessageBox.alert` 纯文本两行（创建时间 / 最后修改）。
- 原设计（[2026-09-13_note-info](../requirements/2026-09-13_note-info/note-info_design.md)）明确「不显示文件大小等额外信息（YAGNI）」——当时只有一个时间需求，现在信息维度确实值得扩展，属于重新评估而非推翻。

## 可复用数据源盘点（全部现成，无需新管线）

| 数据 | 来源 | 成本 |
| --- | --- | --- |
| 创建 / 修改时间 | `noteGetInfo`（`fs.statSync`） | 已有 |
| 文件大小 / 行数 / 字符数 | 同上扩一处：stat 的 `size` + 顺手读文件统计（笔记均为小文件） | 极低 |
| 笔记标签（含颜色） | `noteTags(vault, path)` IPC 已存在（返回 `TagItem[]`） | 零 |
| 所属笔记库 + 外部标记 | `props.vault` + `tree.vaults` 的 `external` | 零 |
| 库的 Git 关联信息 | `tree.gitStatuses[vault]`（侧栏已加载）：`{ associated, repoFullName, remoteUrl, branch, ahead, behind, dirty }` | 零（只读缓存） |
| 被引用数（反向链接） | `wikilinkBacklinks(vault, path)` IPC 已存在 | 零（异步一次调用） |

## 建议分层

### P0 —— 建议本期做（用户点名 + 数据现成）

1. **标签区**：frontmatter 标签胶囊（颜色 / 名称与编辑器折叠行胶囊同款），可点击 → 应用标签筛选并关闭弹窗（复用 FR-2.6 筛选管线）；无标签显示「—」。
2. **所属笔记库**：库名 + 「外部」标记（外部库才有）；草稿（scratch 伪库）此区显示「草稿」。
3. **Git 关联信息**（仅库已关联时显示，未关联整区隐藏）：
   - 仓库 `owner/repo`（remoteUrl 可省，标题 tooltip 展示完整 URL）；
   - 分支名；同步状态 `↑ahead ↓behind`；`dirty` 时显示「有未提交变更」小圆点。
   - **数据口径**：优先读侧栏已缓存的 `gitStatuses`（零子进程开销）；缓存无记录时后台 `getGitStatus` 拉一次。信息弹窗是查看性质，允许略旧，不做手动刷新。

### P1 —— 廉价顺带（建议同车）

4. **大小 / 行数 / 字符数**：`noteGetInfo` 扩展返回（`size` + 读文件统计），客观口径无争议。
5. **库内相对路径** + 复制按钮（复制**绝对路径**，对外部分享 / 终端场景更通用）。
6. **被引用数**：「N 篇笔记引用了本文」，异步加载不阻塞弹窗打开。

### P2 —— 本期不建议（口径 / 成本问题，留待明确需求）

- **写作字数（词数口径）**：中英混排「字数」口径要先定义（中文按字、英文按词？），且用户环境中已有统计类插件先例，与插件生态分工待想清楚。字符数 / 行数已在 P1 覆盖客观部分。
- **本文件最近一次提交时间 / 作者**：`git log` 按文件需子进程调用（Windows 单次 1s+），异步 + 缓存才不卡弹窗，信息价值有限。
- **出链数 / 附件数**：出链需解析正文（成本中），附件数场景弱。

### 维持不做的（沿既有决策）

- **文件夹「信息」**：mtime 不递归更新，显示会误导（2026-09-13 原决策不变）。
- **弹窗内编辑**：只读弹窗；标签增删走既有「标签」菜单项，不在信息弹窗内嵌编辑态。

## UI 形态建议

`ElMessageBox.alert` 纯文本模式到头了（胶囊 / 复制按钮 / 分组都做不了），建议新建 **`NoteInfoDialog.vue` 专用组件**（参照 TagPickerDialog 等既有弹窗模式），两个入口共用。布局草图：

```
┌ test03 信息 ───────────────────────── ✕ ┐
│  所属笔记库   测试用01（外部）            │
│  路径        正反就是测试一下/test03.md ⧉ │
│  创建时间     2026/9/7 15:04:53          │
│  最后修改     2026/10/10 10:52:56        │
│  大小        1.2 KB · 30 行 · 356 字符    │
│  标签        (测试1) (tag_1) (tag_2)     │
│  被引用      3 篇笔记                    │
│  ─────────────────────────────────   │
│  Git 仓库     owner/repo · main  ↑1 ↓0  │
│              ● 有未提交变更              │
│                             [确定]      │
└─────────────────────────────────────┘
```

- 标签区以上同步加载（全部现成数据），「被引用」「Git 缓存缺失回填」异步补入，弹窗先开不转圈；
- 颜色全走 CSS 变量，深浅色自适应；Esc / 遮罩关闭与设置弹窗一致。

## 决策点（立项时拍板）

- **D1 载体**：专用 `NoteInfoDialog.vue`（推荐）vs `ElMessageBox` + VNode 轻改（胶囊可做但交互 / 分组受限）。
- **D2 Git 数据口径**：只读侧栏缓存（推荐，缺时回填一次）vs 每次打开强制刷新（多一次 git 子进程）。
- **D3 标签胶囊是否可点击筛选**：可点（推荐，动线顺）vs 只展示。
- **D4 被引用数是否进本期**：进（IPC 现成）vs 砍掉保最小。
