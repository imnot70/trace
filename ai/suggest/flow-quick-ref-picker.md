## 现状与缺口

心流模式（隐藏侧栏与顶栏）下把别的笔记引入当前写作的动线已有两条：

| 动线 | 入口 | 适用 |
| --- | --- | --- |
| `[[` 扁平补全（FR-2.9.10 P2） | 编辑器输入 `[[` + 名字片段 | **记得名字**时最快；`[[/` 可逐级浏览但面板窄、无层级展开 |
| 搜索弹窗（FR-2.9.11） | Double-Shift | **记得关键词**时；结果可键盘导航 + Alt+Enter 预览 |

缺第三条腿：**不知道 / 记不清名字，想按目录结构翻一翻**时没有入口。

既有的 Alt+B（心流下呼出浮层侧栏）填不了这个缺口，原因有三：

1. 呼出的是**完整侧栏**（常用 / 收藏 / 标签 / 回收站 / 笔记库），写作场景里噪音重；
2. 侧栏点击节点 = **打开笔记**（切换走、丢写作上下文），语义是「跳转」不是「插入引用」；
3. 纯鼠标导向，与心流键盘流（`[[` 补全 / 搜索弹窗均已键盘化）不配套。

## 建议方案

### 方案 A（推荐）：独立「快速引用面板」

一个类搜索弹窗（`SearchDialog.vue` 同构）的轻量浮层，快捷键 + 斜杠命令双入口：

- **入口**：`Alt+I`（Insert，键位候选见决策点 1）呼出 / 再按或 Esc 关闭；斜杠命令 `/引入` 同义（FR-2.4.22 体系）；快捷键速查表登记；
- **面板形态**：左侧紧凑目录树（数据源复用 tree store，仅「笔记库 → 文件夹 → 笔记」三层结构，砍掉常用 / 收藏 / 标签 / 回收站区块）+ 顶部过滤输入框（可选使用——输入即切扁平模糊列表，匹配复用 `lib/noteCompletion.ts`，与 `[[` 补全同一套）；**草稿单独分组**（伪库 `__scratch__`，来自 draft store 的 `scratchList`）；
- **键盘动线**：↑↓ 在树内移动、→ ← 展开 / 收起文件夹、`Enter` 引入、`Alt+Enter` 悬浮预览（复用 app store `pendingNotePreview` 握手，与搜索结果同款）、`Esc` 关闭（走既有应用级 Esc 分级链，插在浮层侧栏之前或同层，见决策点 2）；
- **引入语义**（三路全部复用既有管线，不新造）：
  - 当前库笔记 → `insertReferenceFromCompletion` 同款插入 `[[相对路径]]`（括号一致性处理已内建）；
  - 其他库笔记 → 走 `insert-cross-vault` → `EditorView.insertPreviewTarget`（确认框 → 复制进当前库 → 插入引用；免确认开关自然生效）；
  - 草稿 → 本质是跨库（见决策点 3）；
- **心流适配**：面板遮罩 / 卡片经 `env(titlebar-area-height)` 避让 WCO 三键（v0.13.0 修复已有现成 CSS）；浮层呼出 / 收回不触发打字机重锚（无几何变化，`geometryChanged` 不涉浮层）。

### 方案 B（不推荐单做）：增强 `[[` 补全为完整树浏览

`[[/` 根浏览已是雏形，理论上可扩成完整树。但 CM completion 面板做层级展开交互复杂度高、面板宽度不适合浏览长路径、且「树浏览」与补全的「输入过滤」语义混杂。方案 A 的过滤态已等价覆盖其价值。

### 方案 C（否决）：复用 Alt+B 浮层侧栏改点击语义

心流下把侧栏点击从「打开」改为「插入引用」——破坏侧栏全局语义一致性（同一组件心流内外行为分叉），且完整侧栏形态过重。否决。

## 关键决策点（立项时拍板）

| # | 决策 | 候选 | 倾向 |
| --- | --- | --- | --- |
| 1 | 呼出键位 | `Alt+I`（Insert 语义）/ `Alt+L`（Link）/ `Ctrl+P`（VS Code 惯例，需验证 Electron 下打印冲突） | Alt+I |
| 2 | Esc 分级位置 | 插在分级链最前（面板最临时）与浮层侧栏同层 | 最前 |
| 3 | 草稿引入语义 | a) 与跨库一致：确认后**复制草稿为当前库正式笔记**再引用（推荐，产物可同步）；b) 仅提示「请先转正」（保守，动线断）；c) 直接引用 `[[草稿名]]`（断链——草稿不在双链索引，否决） | a |
| 4 | 库范围 | 一期：当前库 + 草稿；二期：全库树（跨库节点直接挂确认复制语义） | 分期 |
| 5 | 默认落点 | 呼出时定位 / 高亮当前笔记所在文件夹（省一次翻找） | 是 |
