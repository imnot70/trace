# 返回上一笔记与会话内光标记忆（FR-2.4.26）

> 2026-09-30 立项当日实施（分支 `feat/flow-reference-drag`，随 P3 同批发版）。背景：P3 复验讨论中用户提出——搜索结果单击 / Enter 会直接切换笔记，Trace 无多窗口 / 标签，误点后切回最快要走「常用」，心流模式（顶栏隐藏）下影响尤其严重。曾提议「心流限定确认框」，讨论后拍板为**返回能力 + 光标记忆**（覆盖全部误切换入口，不惩罚有意操作，见 D1）。

## 需求

### FR-2.4.26 返回上一笔记与会话内光标记忆

- **A 返回上一笔记**：`Alt+←` 与**最近一次离开的笔记**互切——按下返回（再按切回来，两档来回）；仅编辑视图内生效。心流 / 专注模式同样可用（纯键盘动线，不依赖侧栏）。
- **B 会话内每笔记光标记忆**：离开笔记时存档光标与滚动位置（会话内，不落盘）；**任何方式**重新打开该笔记（搜索 / 双链 / 反向链接 / 侧栏树 / 返回）都恢复上次编辑位置；无存档的笔记按既有「编辑位置」设置（FR-2.4.18 文首 / 文末）落位。设置页往返的光标恢复（2026-09-27 的单槽存档场景）并入本表。
- **取消拖曳语义无关**：本能力只加「回得来」的路，不改变任何既有切换行为（搜索单击仍然直接打开——有意切换保持零摩擦）。

## 验收标准

1. 首页光标置于中部 → 切到随笔 → `Alt+←`：回到首页且**光标恢复到离开时的位置**（逐字符一致）；再按 `Alt+←` 切回随笔（两档互切）。
2. 随笔光标置于任意位置 → 树切首页 → 树切回随笔：光标恢复（不经过 Alt+← 也生效——B 的独立价值）。
3. 无存档的新笔记首次打开：按编辑位置设置落到文首 / 文末（FR-2.4.18 行为不变）。
4. 重开同一篇不算切换：`lastNote` 不被覆盖；无 captureCursor（组件未挂载）时切换不报错。
5. 设置页往返：光标与滚动位置恢复（原 savedCursor 单槽场景，并入 cursorMap 后行为不变）。
6. store 单测覆盖存档 / 互切 / 落位意图分支；CDP 真实手势冒烟覆盖 A3 / B1。

## 决策记录

- **D1 方案 = 返回能力 + 光标记忆，不做心流限定确认框**（2026-09-30 用户拍板）：确认框只堵搜索一个入口（双链 / 反向链接 / 悬浮预览误点同样会切走），惩罚有意切换（切换是廉价可逆操作，不配确认框），且行为按模式分叉。返回 + 记忆覆盖整类问题、全模式一致。
- **D2 两档互切而非全量历史栈**（实现取舍）：误操作恢复需要的是「**紧邻的上一篇**」，两档互切语义最简单可预期（按多少次都在两篇间来回）；更早的笔记走「常用」（既有）。全量前进 / 后退栈如需可另行立项。
- **D3 快捷键 `Alt+←`**（浏览器返回惯例）：应用内无占用（速查表已核）；`Ctrl+Alt+←` 在 Linux 桌面常被工作区切换占用故不取。
- **D4 光标存档仅会话内**（不落盘）：跨会话恢复涉及笔记内容变更后的位置失效问题（外部编辑 / 同步改写），会话内足够覆盖「误切走切回来」场景。
- **D5 双档互切升级为前进/后退栈**（2026-09-30 同日，用户提出「最近 n 篇」）：双档互切就是深度为 1 的前进/后退栈——升级不改变 A→B 场景手感（Alt+← 仍是「退一步」），深度历史时每按一步多退一层（旧实现只能在最后两篇间震荡）。`Alt+←` 后退 / `Alt+→` 前进（浏览器模型），新开导航清空前进栈；导航记账在 openNote 内部按 mode（new / back / forward）区分；笔记删除剪枝、重命名 / 换库名跟随改写。
- **D6 MRU 快切面板**（2026-09-30 同日，用户拍板「栈 + MRU 都做」）：VS Code Ctrl+Tab 模型——**按住** `Ctrl+Tab` 弹出最近打开面板（会话内记序，新→旧，上限 15 篇），`Tab` / `Shift+Tab` 翻动（跨组件响应 repeat，按住连翻），**松开 Ctrl 提交**跳转，`Esc` 取消；开面板默认选中 index 1（上一次的笔记——零额外按键 = 跳回上一篇的肌肉记忆）；不足 2 篇不启用。提交为普通打开（记账进后退栈）。窗口失焦取消（keyup 可能丢失）；MRU 面板打开期间弹出系统对话框（跨库确认框等）立即取消（键归对话框）。
- **D7 条目级光标快照**（2026-09-30 用户复验观察「历史中同一笔记出现多次、光标不同」后拍板）：历史条目 = 一次**到访**（浏览器同款语义，同一笔记被再次访问后会再压一条，重复是 feature 不能去重——去重破坏原路返回的前后栈对应）；此前恢复查 cursorMap（全笔记最新一份），现改为**压栈时把该次离开的选区 / 滚动快照进条目**（`HistoryNote.cursor`），后退 / 前进经 `pendingCursor` 下发恢复「那一次」的光标——重复条目成为真正的按到访回溯。MRU 提交 / 普通打开维持查 cursorMap（最新）。心流下更明显的原因：心流动线只依赖 Alt+←/→（来回访问频繁），常规模式多用 Ctrl+Tab（MRU 按最新去重，天然无重复）。

## 实现要点（设计）

- `editor` store：`cursorMap: Record<'vault::path', { anchor, head, scrollTop }>`（原单槽 `savedCursor` 并入）+ `lastNote` + `goBackNote()`（经 `openNote` 走正常打开管线，互切由 openNote 自动回写 lastNote 实现）+ `captureCursor` 上报槽（store 拿不到 CM 视图，MarkdownEditor 挂载时注册实时选区读取器）；
- `pendingPlacement` 扩展 `'remembered'`：openNote 时目标笔记在 cursorMap 有存档 → remembered（恢复上次位置），否则按 FR-2.4.18 设置；MarkdownEditor 的 `applyPendingPlacement` 消费（clamp 到文档长度 + scrollIntoView + rAF 恢复滚动）；
- 快捷键 `Alt+←` 挂 App.vue 全局键（编辑视图 + 当前笔记守卫），速查表编辑器分组登记；
- tsconfig.node include 补 `src/renderer/src/env.d.ts`：store 测试经传递引入 `stores/app`（`window.trace`）需要该全局声明（DOM 库由第三方包的 lib reference 顺带带入，故 `document` 可用而 `window.trace` 不可用的根因）。

## 边界修复：历史尽头按键漏给 CM 行边界移动（2026-09-30 真机反馈，当日修复）

- **现象**：后退 / 前进栈走到头再按 `Alt+←` / `Alt+→`，光标上 / 下跳一行（心流下表现为内容反向滚动、锚定正常）。
- **根因**：栈空时 `goBackNote` 静默返回，但按键已漏进 CM defaultKeymap 的 `Alt-ArrowLeft/Right`（行边界移动 `cursorLineBoundaryBackward/Forward`）——CM 在 contentDOM 层先于窗口层处理，窗口层的 preventDefault 是事后诸葛（同 Ctrl+S 双 toast 机制）。
- **修法**：① `MarkdownEditor` 的 Prec.high 键位表新增 `Alt-ArrowLeft/Right` **无条件消费**绑定（转发 `goBackNote` / `goForwardNote`）——栈非空正常导航，栈空只吞键不动光标（无条件 return true，符合键位教训的安全形态）；② `App.vue` 窗口层两分支加 `defaultPrevented` 守卫（CM 已消费则跳过），防同一击双跳（消耗两条历史）。
- **验证**：CDP 6 项全过——栈空 Alt+← 光标逐字符不动（连按两次）、前进栈空同理、编辑器聚焦 + 栈非空导航一步且 backStack 只消耗一条（双跳守卫生效）。
