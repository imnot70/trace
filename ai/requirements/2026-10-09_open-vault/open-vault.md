# 打开已有笔记库（外部笔记库）（FR-2.1.4）

> 2026-10-09 立项并当日实施（分支 `feat/open-vault`，基线 v0.19.0）。用户提出：希望能把 GitHub 上的笔记 clone 到本地后直接用 Trace 打开，并自动完成关联。

## 需求背景

Trace 的笔记库模型是「工作区（默认 `~/Trace`）下的一级子目录」，GitHub clone 的仓库通常落在用户自选的任意位置（不在工作区内），此前无法用 Trace 打开。用户手动迁移进工作区又会打断既有 git 历史与路径习惯。

## 需求

### FR-2.1.4 打开已有笔记库（外部笔记库）

- 创建笔记库弹窗（侧栏「笔记库」区「+」与欢迎页「创建笔记库」按钮共用）增加**标签页**：「创建笔记库」｜「打开已有笔记库」；
- 「打开」标签页：说明文案 + 「浏览…」按钮（系统目录选择器）+ 选中路径回显 + 「打开」确认；
- 选择**工作区之外**的既有目录注册为笔记库：
  - 目录名即库名（须符合笔记库命名规则；与现有库重名大小写不敏感拒绝；重复打开同一目录幂等返回既有注册名）；
  - **仅登记映射，不移动 / 复制 / 改写用户目录**（注册表存 userData/open-vaults.json）；
  - Git 仓库**自动识别远程**：Trace 的关联态直接读 `.git` 的 origin remote——clone 下来的仓库天然「已关联」，git 状态徽标与一键同步（PAT 调用时注入）即刻可用；无远程的目录照常打开，可通过库菜单关联；
- 外部库的行为分流：
  - 侧栏库行带「外部」标记（title 说明删除语义）；
  - 重命名 = 仅改 Trace 内显示名（弹窗标题注明），磁盘目录名不动；
  - 删除 = 仅解除注册，确认文案明示「磁盘上的目录与文件不会被删除」，成功提示区分；
- 外部库与工作区库同权：文件树 / 编辑保存 / 全局搜索 / 双链索引 / 标签 / 回收站（跨盘自动回退复制删除）/ 文件监听（独立 chokidar 实例，同一防抖与挂起管线）全部生效。

### 非目标

- 不做「从 GitHub URL 直接 clone」（用户用任意工具 clone 后打开即可，避免在应用内复制一套 clone 进度管理）；
- 不做外部库的批量打开 / 目录扫描自动发现。

## 验收标准

1. 「+」弹窗出现两个标签页，「打开已有笔记库」可选择目录并注册，侧栏出现带「外部」标记的库；
2. clone 样目录（含 origin remote）打开后 git 徽标显示已关联，可直接同步；
3. 外部库笔记可打开编辑保存（磁盘真值正确），全局搜索可命中；
4. 移除外部库仅解除注册，磁盘文件原样保留；重新打开恢复；
5. 工作区内库的创建 / 重命名 / 删除（回收站）行为零回归。

## 备注

- 工时评估：1~1.5 天（主进程注册表与分流 0.5 / watcher 与 trash 0.25 / 弹窗与接线 0.5 / 测试与文档 0.25）。
