# 窗口最小宽度保护设计

> 状态：**实施中**（fix-min-width 分支）
> 约束：PRD 已知局限——"极窄窗口（<1080px）下编辑区最小宽度受限"

## 1. 问题

窗口缩得很窄时，主区卡片（编辑/预览/欢迎/设置等）会随容器等比压缩至无法阅读或点击，但侧栏固定 272px 不参与压缩——视觉上出现"侧栏挤占主区、主区消失"的情况。

## 2. 设计立场

不引入响应式折叠（工作量大、行为复杂），而是**在 CSS 层设置弹性 min-width**：窗口宽于阈值时自由缩放；窄于阈值时主区不再压缩，整体出现横向滚动条。这是最简单的方案，与 Electron 桌面应用的定位一致。

## 3. 方案

### 3.1 阈值

- **整体窗口**：`app-shell` 设 `min-width: 800px`——低于此宽度后，Electron 窗口本身不可再缩小（与 `BrowserWindow.minWidth: 1080` 已有约束共同生效，Electron 窗口不可缩于 minWidth）
- **主区卡片**：`main-cards` 设 `min-width: 0`（现值，保持——它作为 flex 子项允许 flex-basis 归零，由内部卡片的 min-width 接管）
- **编辑卡**：`editor-card` 设 `min-width: 480px`——这是 40 字/行的底线，CodeMirror 40 字宽约 480px（12pt 等宽字体 + 行号 60px）。低于此值后编辑卡不再缩放，分隔条到编辑卡右边缘的剩余空间分给预览
- **预览卡**：`preview-card` 设 `min-width: 280px`——保留最小可读宽度
- **编辑卡 + 预览卡**加起来 770px，加 10px 分隔栏 = 780px；侧栏 272px + 画布 padding 10px + 10px = 292px；合计 1072px——刚好落在 `minWidth: 1080` 窗口约束之下

### 3.2 page-card（非编辑视图）

- `page-card` 设 `min-width: 500px`——欢迎/回收站/设置页面不希望被压缩至无法操作

### 3.3 不做

- 不做响应式折叠（如侧栏收起/自适应列数）——属于 FR-2.9 设计范围外，且当前收起侧栏功能已覆盖部分场景
- 不做滚动条美化——`overflow: auto` 的原生滚动条在 Electron 里表现足够

## 4. 量化评定

| 项 | 值 |
| --- | --- |
| 代码量 | 约 15 行 CSS（3 处 min-width 声明） |
| 工作量 | **约 30 分钟**（含隔离实例验证） |
| 风险 | 极低——纯 CSS 声明，无运行时逻辑 |

## 5. 验收

- [ ] Electron 窗口拖到最小（1080px），编辑区仍然可正常编辑、预览区可见
- [ ] 极窄（如强制缩到 <800px 的场景——通过 DevTools 模拟），出现横向滚动条而非内容消失
- [ ] page-card（欢迎页/设置页）在窄窗口下不被压缩至无法操作
