# 所见即所得编辑模式（Live Preview）需求

> 创建：2026-09-21 ｜ 状态：**已实施（随 v0.6.0 发布）**，实施记录见 [wysiwyg_design.md](wysiwyg_design.md) 第 10 节
> 本文档记录需求确认结论（做什么、为什么）；技术方案（怎么做）见 [wysiwyg_design.md](wysiwyg_design.md)。

## 1. 背景与目标

当前编辑器为 CodeMirror 6 源码模式 + 右侧分栏实时预览（markdown-it 渲染管道）。源码模式要求用户理解并书写 markdown 语法，对非技术用户不友好。

本功能为目标提供**所见即所得的编辑体验**，同时不破坏项目根本原则：

- **文件是唯一事实来源**：磁盘上始终是纯 `.md` 文件，所见即所得只是编辑器呈现层，不引入私有格式；
- **与既有能力全兼容**：双链、补全、插件工具栏按钮、快捷键、自动保存、外部修改保护等在两种模式下行为一致。

属二期 Backlog「所见即所得编辑模式」毕业项（Backlog 最后一项功能）。

## 2. 决策记录（2026-09-21 需求确认）

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| D1 | 体验形态 | **Live Preview（Obsidian 式）**：markdown 源码为基础，非光标区域渲染呈现（标题大字、加粗生效、公式出图），光标所在处显示语法源码 | 备选为「真 WYSIWYG（Typora 式）」——需引入 ProseMirror 系编辑器重写编辑层（10–15 人日起步），双链/补全/插件工具栏需重做适配、风险高；Live Preview 基于现有 CodeMirror 6 扩展实现（预估 5–8 人日），架构延续性最好，且随时可回退源码模式 |
| D2 | 预览分栏处理 | **进入时自动收起预览、编辑区占满**；切回源码模式恢复原分栏比例 | 所见即所得时预览卡内容重复、语义多余；自动联动避免用户手动管理布局 |
| D3 | 首版特性范围 | 基础语法全含 + 四组进阶特性（见 FR-W4–W7） | 四组全选：公式/高亮、双链、表格/任务列表、内嵌 HTML/frontmatter 均为已发布能力，不覆盖会造成体验断层 |
| D4 | 切换与记忆 | **全局默认（设置项）+ 顶栏按钮 / 快捷键随时切换**；首版不做单篇记忆 | 全局一个状态心智负担最低；单篇记忆留待真实反馈后评估 |

## 3. 功能需求

### FR-W1 模式切换

- 编辑器顶栏提供模式切换入口（按钮或开关），快捷键 **Ctrl+E** 切换（当前快捷键表无冲突，`config/shortcuts.ts` 需登记）；
- 设置 → 编辑器新增「默认编辑模式」（源码模式 / 所见即所得），新开笔记按默认模式打开；
- 切换即时生效，滚动位置与光标位置保持（不跳到文首）。

### FR-W2 Live Preview 渲染

- 非光标区域按渲染后形态呈现，渲染效果与右侧预览管道一致（同一套样式语言，`markdown.css` 复用）；
- 光标所在行/块恢复显示 markdown 源码，光标移开后重新渲染；
- 源码为唯一事实：任何时刻底层文档都是标准 markdown 文本，保存产物与源码模式完全一致。

### FR-W3 预览分栏联动

- 进入所见即所得：自动收起预览分栏，编辑区占满（含用户此前手动收起之外的场景）；
- 切回源码模式：恢复进入前的分栏状态与比例；
- 与 Alt+V（显示/隐藏预览区）、专注模式、悬浮预览的交互在技术设计中细化（原则：所见即所得期间预览区强制收起，Alt+V 不展开；悬浮预览不受影响）。

### FR-W4 渲染增强：LaTeX 公式 + 代码高亮

- 行内 `$...$` 与块级 `$$...$$` 公式实时渲染（KaTeX，与预览同款）；
- 代码块语法高亮（与预览同款 16 语言随主题）；
- ~~已知局限延续：列表项内块级公式（markdown-it-texmath 局限）在编辑器内不要求优于预览~~（该局限已在渲染管道层修复——列表项内句中公式行内呈现、多行块级正常识别，编辑器与预览一致）。

### FR-W5 双链 + 补全

- `[[笔记名]]` 渲染为可点击链接（点击打开/消歧候选），断链删除线样式，与预览行为一致；
- `[[` 逐级路径补全、`#` 锚点补全在所见即所得模式下继续可用。

### FR-W6 表格 + 可交互任务列表

- GFM 表格渲染为真表格；光标进入表格区域显示源码以便编辑（首版不做 GUI 表格编辑器）；
- 任务列表渲染为复选框，所见即所得模式下**可点击切换勾选态**（写回源码 `- [x]` / `- [ ]`，走正常保存流程）。

### FR-W7 内嵌 HTML + frontmatter 折叠

- 经 DOMPurify 净化的内嵌 HTML 以渲染效果呈现；编辑该区域时显示源码（净化规则与预览一致）；
- frontmatter（标签存储区）折叠为一行摘要展示，不渲染为正文；光标进入展开源码。

### FR-W8 设置与状态

- 设置 → 编辑器：默认编辑模式选择；
- 插件声明式工具栏按钮、编辑器格式化快捷键（Ctrl+B/I/Shift+X）、命令在两种模式下照常工作。

## 4. 非目标（首版不做）

- 真·所见即所得（完全无源码形态，ProseMirror 重写）；
- 单篇/单笔记的模式记忆；
- 表格 GUI 编辑器、图片可视化调整；
- 移动端/窄窗口专项优化（沿用现有最小宽度保护）。

## 5. 验收标准

1. Ctrl+E 与顶栏按钮可在两种模式间往返切换，光标与滚动位置保持；
2. 默认模式设置生效：设为所见即所得后新开笔记直接进入该模式；
3. 基础语法（标题/粗斜体/删除线/列表/引用/链接/图片/行内代码/代码块/水平线）渲染形态与预览一致，光标行正确回落源码；
4. FR-W4–W7 四组进阶特性逐项可用，任务列表点击勾选能写回源码并触发自动保存；
5. 进入/退出模式时分栏按 FR-W3 联动，Alt+V / 专注模式 / 悬浮预览无异常；
6. 插件工具栏按钮、双链补全、格式化快捷键在所见即所得下正常；
7. 磁盘产物验证：编辑后保存的 `.md` 与源码模式编辑结果一致（无格式漂移）；
8. 长笔记（≥5000 行）切换与输入无可感知卡顿（具体指标技术设计定）；
9. 既有单元测试不回归；渲染装饰逻辑有单元测试覆盖。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 编辑器内渲染与 markdown-it 预览效果不一致，产生「两套渲染」心智 | 技术设计阶段明确复用边界：样式类复用 `markdown.css`，语法解析尽量共享规则；验收标准 3 逐项比对 |
| 长笔记性能（逐行装饰计算） | 设计阶段确定装饰策略（视口优先/增量更新），验收含 5000 行性能项 |
| 高频事件（输入、光标移动）触发过度重渲染 | 复用现有防抖/节流经验（悬浮预览滚动同步 100ms 防回环同类手段） |
| Ctrl+E 与用户习惯冲突（如浏览器地址栏联想肌肉记忆） | 快捷键在设置速查表中可见；如反馈强烈再评估可配置化（不在首版） |
