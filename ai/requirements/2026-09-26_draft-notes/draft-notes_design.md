# 草稿笔记 — 技术设计

> FR-2.3.9，2026-09-26。分支：待建（建议 `feat/draft-notes`，基于 main v0.8.7+）。

## 1. 架构：伪笔记库（v2 方案，用户定稿）

草稿是**真实文件**，存放在应用数据目录 `userData/scratch/`，以一个**内部伪库**接入现有文件体系：

- 伪库 vault 常量：`SCRATCH_VAULT = '__scratch__'`（用户库命名校验不允许该形态，不会冲突）；
- 文件 IPC 入口按 vault 特例解析：`readNote` / `saveNote` / `deleteNote` / `fsTree.list` / `createNote` 判断 `vault === SCRATCH_VAULT` → 路径解析到 `userData/scratch/`（不走工作区 resolveWithin，改走 scratch 目录内的等价校验）；
- 图片资产：`userData/scratch/assets/`，`trace-vault://` 协议对 scratch 库同样特例（FR-2.5 管线复用）。

**v2 相对初版（内存缓冲区）的决定性优势**：内容被自动保存（1s 防抖）持续写入真实文件，「未落盘」状态不存在——崩溃安全、天然支持多份草稿；大部分子系统因「scratch 不在工作区」**自动获得正确行为**（见 §2），无需逐一容错。

## 2. 自动排除范围（特性，非缺陷）

草稿不在工作区，因此以下子系统**天然不涉及**，无需代码：

| 子系统 | 行为 | 语义 |
| --- | --- | --- |
| 全局搜索 | 索引默认只扫工作区库 | 草稿默认不可搜；搜索范围下拉提供「草稿」选项（显式勾选后可搜，见 §3.5）——写着写着想回看之前草稿的场景需要它 |
| 双链 / 反向链接索引 | 同上 | 草稿中的 `[[引用]]` 不算数 |
| 标签索引 | 同上 | 草稿 frontmatter 的 tags 不进标签体系 |
| Git 同步 / 自动同步 | scratch 非 git 仓库 | 草稿永不同步；转正后才进入同步体系 |
| 回收站 | 草稿删除为永久删除 | 「临时」语义 |

需要**显式处理**的守卫（guard 清单）：

| # | 位置 | 处理 |
| --- | --- | --- |
| G1 | `fs:saveNote` / `fs:readNote` / 删除 / 列表 IPC | vault 特例解析到 scratch 目录 |
| G2 | editor store `addRecent` | scratch 笔记跳过（转正后路径变更，避免常用列表失效） |
| G3 | 收藏入口 | scratch 笔记不显示收藏（转正后可用） |
| G4 | `Ctrl+S` / 保存按钮 | 草稿态拦截 → 转正对话框（不发常规保存 IPC） |
| G5 | 粘贴 / 拖入图片 | 写入 `scratch/assets/` 而非库附件目录 |

## 3. 交互设计

### 3.1 创建（Ctrl+N）

- 当前为草稿且内容 trim 后为空 → 聚焦该草稿（不生成空文件）；
- 否则创建 `速记 MMDD-HHmm.md`（重名追加序号 `-2`、`-3`）并打开、自动聚焦。

### 3.2 侧栏「草稿」菜单

- 位置：左侧栏「常用」下方；**草稿存在时才显示**（不打扰空态）；
- 列表：草稿名（去扩展名）+ 相对时间，点击打开（editor.openNote 到 scratch 伪库）；
- ⋮ 菜单：转正为笔记 / 删除（红字，永久删除 + 确认）。

### 3.3 转正（Ctrl+S / 保存按钮 / 侧栏 ⋮「转正为笔记」）

对话框（复用 `MoveDialog` 树形选择器组件）：

1. 目标库（下拉，现有库列表）+ 目录（树形选择，默认 = 当前位置上下文）+ 笔记名（默认去掉草稿名的时间戳，可改，重名校验）；
2. 确认后：`createNote(vault, dir, name, content)` 建正式笔记 → 若 `scratch/assets/` 有该草稿引用的图片：复制进目标库 `attachmentsDir` 并**改写引用路径前缀**（`assets/` → `attachmentsDir/`）→ 删除 scratch 草稿文件与已迁资产；
3. `editor.current` 切换到正式路径 → `addRecent` 开始正常记录 → 提示「已转正」。

心流模式下转正对话框以浮层呈现（与浮层侧栏同思路）。

### 3.4 顶栏 / 状态区

- 顶栏保存按钮：草稿态 title 变为「转正为笔记 (Ctrl+S)」；
- 心流右下角状态区：草稿态保存圆点语义不变（未保存淡显——自动保存到 scratch 也算「已保存」，圆点静置）。

### 3.5 搜索集成与跨库插入校验（2026-09-26 设计补充，用户提出）

**场景**：写着写着想回看之前临时记录的内容——草稿标题是时间戳（无可记忆性），必须靠**内容搜索**才能找回，因此草稿需进入搜索范围。

**搜索范围设计**：

- `SearchService` 的库枚举纳入 scratch 伪库（显示名「草稿」，目录非空时出现）；搜索结果项的库徽标显示「草稿」，点击打开走 G1 特例（readNote 已覆盖）✓；
- 搜索框范围下拉（所有库 / 各库清单）中出现「草稿」；「所有库」语义**包含草稿**（用户可单独取消勾选）。

**引入的问题与对策**（评估结论）：

| 问题 | 对策 |
| --- | --- |
| 草稿文件变更 watcher 看不到（watcher 只监听工作区） | 草稿自动保存落盘后**手动调** `search.updateFileIndex(SCRATCH_VAULT, path)`；转正 / 删除时对应 remove |
| 「所有库」语义变化 | 草稿作为独立可勾选项进入库清单，用户可取消；默认勾选 |
| **跨库插入断链**（与下条校验联动） | 见下方插入校验——草稿搜索预览的插入必须同样校验 |

**跨库插入校验（登记为待办，优先级中高）**：双链只在**库内**解析（FR-2.4.11 既有语义），因此——

- 在正式笔记 A（库 X）中，通过搜索预览了库 Y 的笔记并 Alt+Enter / 按钮插入 → 产出的 `[[名字]]` 在库 X **永远断链**，且当前无任何提示（v0.8.6 起即存在，多库 + 跨库搜索的用户才会踩）；
- 校验规则：插入前比对 `previewTarget.vault` 与 `editor.current.vault`——**不一致则阻止插入**，明确提示「{笔记名}」位于「{库名}」库，与当前笔记不同库，暂不支持跨库引用（预览保留，用户可自行摘抄内容）；
- 同样约束「插入引用」按钮；`[[` 补全插入不受影响（补全源本就只来自当前库，天然同库）；
- **草稿特例（待决 D6）**：草稿没有归属库，预览正式库笔记后插入引用——转正进入该库则可解析、进入其它库则断链。倾向**允许插入不校验**（草稿是暂存，写作自由优先；转正对话框可加「引用所在库校验」提示），实施时再确认。

## 5. 决策记录

- **D1 架构 = 真实文件伪库**（用户方案，2026-09-26 定稿）：替代初版内存缓冲区——自动保存持续落盘消灭「未落盘丢失」，多份草稿天然支持，子系统自动排除（对照表见 §2）；难度由 ★★★ 降至 ★★☆。
- **D2 菜单名 = 「草稿」**（候选：速记 / 暂存）。
- **D3 草稿贴图 = 方案 a**：图片进 `scratch/assets/`、转正随迁改写（快速记录时贴图常见）。
- **D4 Ctrl+N 空草稿复用**，非空才新建。
- **D5 草稿删除 = 永久删除**（红色确认），不进回收站。
- **D6 草稿进入搜索范围**（2026-09-26 补充，用户提出「写着写着想看之前的临时记录」）：以独立 scope 选项进入搜索下拉；跨库插入断链由插入校验待办兜底。**已按 §3.5 实施**：结果徽标显示「草稿」、范围下拉独立勾选、「所有库」语义包含草稿、自动保存增量索引。
- **D7 草稿内插入正式笔记引用的策略**：**已决议并实施「允许不校验」**（草稿暂存自由优先）——`canInsertReference` 对 scratch 例外放行；转正对话框的引用所在库提示暂不加（提示语已说明转正语义），有需要再补。

- **实施中修正的四个缺陷**（均已随分支修复并回归）：
  1. **草稿无自动聚焦**（验收 1）：`focusEditorOnce` 原在 EditorView.onMounted 消费，但「打开笔记 + 切视图」时 openNote（异步 IPC）晚于挂载完成、editorRef 未绑定，`?.focus()` 静默落空——改为**观察 editorRef 绑定的 watcher** 统一消费；draft store 增 `focusDraftEditor`（编辑视图已挂载直接聚焦内容层，未挂载置标志）。
  2. **窗口级 Ctrl+S 无草稿分流**（G4 违约）：EditorView 的 window keydown 无条件 `flushSave`——草稿态弹不出转正框反而走常规保存（且与 CM keymap 的 save 事件双层触发）。分流收敛进 `onEditorSave`，CM keymap 与 window 层统一调用。
  3. **搜索结果 / 范围下拉显示原始 `__scratch__`**（违背 §3.5 徽标要求）：SearchDialog 的结果徽标、下拉项、单选库标签统一经 `scratchVaultLabel` 映射为「草稿」；范围下拉经 `scratchStatus` 在草稿存在时追加草稿项。
  4. **创建草稿后侧栏菜单不刷新**：watcher 看不到 scratch 目录，`createDraft` 后补 `refresh()`。
- **验收标准覆盖**：1 ✓；2 ✓（杀进程重开）；3 ✓（搜索按 D6 设计可搜且徽标正确；双链 / 标签 / 同步按 §2 天然排除，常用列表实测排除）；4 ✓（贴图 + 转正后引用与显示正确）；5 部分 ✓（文件移入 / scratch 移除 / 常用与搜索可检索已验，「Git 变更可见」因测试库无远端未覆盖——转正后即普通笔记，机制一致）；6 ✓（侧栏 ⋮ 红色确认走 ElMessageBox，服务层永久删除由单测覆盖）。
