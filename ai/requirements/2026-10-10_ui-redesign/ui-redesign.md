# UI 现代化改造（A+B 组合）需求文档

> 来源：用户反馈「界面有十年前的设计感」→ 诊断 → 三方向静态视觉稿评审 → 拍板 A+B 组合 + 主题包方案 a。
> 视觉稿（可交互，五套皮肤 × 深浅主题 × 并排对比）：[../../suggest/ui-redesign-2026-10/index.html](../../suggest/ui-redesign-2026-10/index.html)（思路存档，立项后保留）。

## 1. 背景与问题

2026-10-10 用户反馈界面整体「有十年前的设计感」。对 `main.css / themes.css / markdown.css / App.vue` 的诊断结论，年代感来自六个可指认的来源：

1. **配色是 2014–2017 GitHub Primer 配方**：`--accent: #4078d3` 企业蓝 + `#f5f6f8` 冷灰画布 + `#24292f` 正文，大面积描边盒子；
2. **边框撑起整个界面**：卡片 / 页头 / 页脚 / 表格 / 代码块 / 设置块全是 1px 实线，缺乏明度分区与阴影层级；
3. **Windows 首命中字体是微软雅黑**，且字号体系扁平（11–14px 挤在一起），层级靠「变灰」不靠「变大变粗」；
4. **Element Plus 出厂形态未精修**：弹窗 / 按钮 / 输入框 / 下拉的骨架样式是 EP 默认皮肤，动效与应用两张皮——弹窗一开就「露馅」；
5. **细节 token 无体系**：圆角 4–20px 混用、动效仅背景色过渡、滚动条常驻 8px 经典款、logo 是 135° 蓝→紫渐变；
6. **排版是「GitHub 技术文档」式**：h1/h2 下边框线、全网格线表格、灰引条 blockquote，不是「笔记应用」排版。

## 2. 目标与非目标

**目标**：

- 三平台（Windows / Linux / macOS）观感一致的现代化视觉，建立可维护的设计 token 体系（圆角 / 阴影 / 动效 / 颜色全部走 CSS 变量，延续既有规范）；
- 确立 Trace 的视觉身份：「chrome 冷静克制、内容温暖如纸」——内容区纸面与心流模式写作底色同源，讲同一个故事；
- 主题包机制**不受破坏**：现有主题包与内置预设继续工作，能力增量式扩充（方案 a）。

**非目标**：

- 不引入任何 OS 级视觉特性依赖（玻璃 / 材质。C 琉方案本体放弃，仅摘选纯 CSS 元素，见 D1）；
- 不改信息架构与交互流程（纯视觉层；唯一结构性调整是侧栏分组标签化，行为不变）；
- 不做主题编辑器、界面自定义字体选择器（将来另议）；
- 不动 WCO 标题栏 / 玻璃开关等既有平台适配成果。

## 3. 方向决策（D1）

三方向经视觉稿评审：

| 方向 | 定位 | 结论 |
| --- | --- | --- |
| A 墨 | 精修中性 chrome：暖中性色 + 明度分区去描边、单一靛蓝交互色、token 归一、字体栈换新 | ✅ 采纳（骨架） |
| B 纸 | 内容优先：暖纸内容面（与心流纸面同源）+ 衬线标题 + 16px 排版 | ✅ 采纳（内容面） |
| C 琉 | 原生玻璃：亚克力卡片叠壁纸、大圆角、胶囊控件、Fluent 微交互 | ❌ 本体放弃；**大圆角 / 胶囊控件 / 按下反馈等纯 CSS 元素摘选进 A+B** |

**D1 拍板：A+B 组合**。C 琉放弃理由（跨平台分级成本）：其玻璃质感依赖 `backgroundMaterial`（仅 Win11 22H2+），Win10 / 材质失败环境自动降级为不透明（`src/main/index.ts` 既有逻辑），macOS 无系统级模糊需另做 vibrancy，Linux 因合成器限制（GNOME 不模糊透明窗口、浅色壁纸方形轮廓前科）只能实色——意味着维护三档视觉验收且身份依赖 OS 特性；A+B 的身份不依赖任何 OS 特性，三平台像素级一致。

## 4. 功能需求

### FR-2.9.13 界面视觉现代化（A 墨 · chrome 层，已立项待实施）

- **中性色重做**：浅色 = 暖白画布 + 纯白卡面；深色 = 近黑画布 + 深灰卡面（取值见设计文档变量表）；层级靠「画布深一档 + 卡面 + 极淡 hairline + 柔和阴影」分区，**描边机制保留、默认值调淡**（不删除 border——主题包与高对比度预设通过 `--border-color` 即可恢复强描边，见 FR-2.9.15）；
- **accent 单一化**：靛蓝系（浅 `#4F5BD5` / 深 `#7E89F2`，实施定稿），只用于交互态（选中 / 焦点 / 链接 / 主按钮），不做装饰性用色；
- **圆角三档归一**：控件 / 卡片 / 浮层（约 7 / 12 / 16px，实施定稿），替换现存 4–20px 混用；
- **动效 token**：统一时长与缓动（约 160ms `cubic-bezier(0.2,0,0,1)`），EP 弹层入场 scale 0.98→1 + fade；主题切换 cross-fade 保留；
- **滚动条 overlay 化**：细条、平时透明、悬停浮现（替换常驻 8px）；
- **字体栈升级**：打包 MiSans（免费商用授权），栈序 MiSans → HarmonyOS Sans SC → PingFang SC → Microsoft YaHei 兜底——三平台渲染一致（现状 Windows 落雅黑 / macOS 落苹方 / Linux 看发行版，各自为政）；
- **Element Plus 适配层**：`--el-*` 映射扩充与弹窗 / 按钮 / 输入框 / 下拉 / message / tooltip 精修，对齐应用设计语言与动效；
- **logo 去 135° 蓝紫渐变**，重绘为扁平色块字标；
- **侧栏分组标签化**（唯一结构性调整）：快捷入口 / 标签 / 笔记库改为「小号分组标签 + 行」结构，点击行为与现有区块标题完全一致；
- **空状态统一**：图形 + 一个主操作按钮（替换现状 0.5 透明度裸图标）。

### FR-2.9.14 纸感内容面（B 纸 · 内容层，已立项待实施）

- **内容区换暖纸底**：编辑器与预览的内容面不再用 `--bg-primary`（白卡），改用独立纸面 token——浅色 `#f8f3e6`（与心流「米黄纸」`--flow-paper-cream` **同源**）、深色 `#2a271f`；chrome（侧栏 / 顶栏 / 工具栏）保持中性；
- **衬线标题**：文档标题与 h1–h3 用衬线字体（打包 LXGW 文楷或思源宋体，OFL 授权），正文保持黑体；设置 → 通用 → 外观新增「衬线标题」开关（**默认开**）；
- **排版重做**（预览与所见即所得**两套同步**）：h1/h2 去 GitHub 式下边框、纯字重字号层级；正文 16px / 行高 1.85；表格改横线式、单元格内边距加大；引用条 accent 弱化底；代码块去描边；
- **与心流模式共存**：日常纸面与心流纸面是两套独立变量（同源不同权）；心流内用户另选纸色（绿 / 蓝 / 粉 / 灰）时允许底色切换，属预期行为。

### FR-2.9.15 主题系统适配与扩充（方案 a，已立项待实施）

- **白名单 19 → 21**：新增 `--content-bg`（内容区纸面底色）与 `--doc-ink`（正文墨色）进入主题包白名单，主题包**可选覆盖**；未覆盖时使用内置纸面默认值——修复「纸面落地将导致主题包染不到正文区」的语义断裂（D2）；
- **新 token 全部走变量**且深浅两套给默认值（`--shadow-*` / `--radius-*` / `--motion-*` 等）——否则第三方深色主题上会浮着对不上的暖黑阴影；
- **内置四预设重调**：warm / cool 适配新体系；**高对比度保留描边例外**——高对比度用户可能正依赖 1px 边框分辨区域，其预设值将 `--border-color` 调至高对比值即可（描边机制未删，无需特判代码，见 D4）；
- **兼容性验收**：现有主题包（部分覆盖与全覆盖样张）在新体系下深浅两态过一遍，无不可读 / 发脏区域；`guides/theme-import.md` 变量表同步（19 → 21 项）。

## 5. 决策记录

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 方向拍板 A+B 组合；C 琉本体放弃、纯 CSS 元素摘选 | 见第 3 节；平台分级成本 + 身份不依赖 OS 特性 |
| D2 | 主题包方案 a：白名单 19→21（`--content-bg` / `--doc-ink`） | 纸面落地后 `--bg-primary` 只影响 chrome；不扩白名单则主题包染不到正文区，用户会当 bug 报。成本一行白名单 + 文档，主题包能力反而变强；备选方案 b（纸面做成预设主题而非默认）已否决——B 从「产品身份」降格为「可选皮肤」与立项初衷相悖 |
| D3 | 字体打包：**MiSans 经 `misans` npm 包引入**（unicode-range 全集子集 woff2，Regular / Medium / Demibold 三字重；二进制不入库走依赖，对齐内置 Git 先例；实施实测构建产物 +5.8MB）；衬线标题 LXGW 文楷 / 思源宋体（OFL）于 P3 打包 | 立项时原定「全量 TTF 不做子集」，实施发现 npm 包为 unicode-range 全集切分（每字符必落在唯一分片、按需下载），**无静态子集的缺字风险**，体积从 15–30MB 预算降到 +5.8MB，口径随之修正 |
| D4 | 高对比度保留描边：依赖「描边机制保留、默认调淡」的实现方式 | 去描边伤害依赖边框分辨区域的低视力用户；机制保留后预设只需调 `--border-color`，零特判代码 |
| D5 | 衬线标题做设置开关（默认开）；纸面底色**不做**独立开关（主题包覆盖 `--content-bg` 为出口） | 衬线是强口味，给出口；纸面是产品身份，开关会碎片化，不喜欢者经主题包换底色 |

## 6. 验收标准

1. 三平台安装包视觉一致，无 OS 特性依赖；Linux 底部圆角规避（`no-bottom-radius`）行为不变；
2. 组合矩阵全过：{浅色, 深色} × {默认, warm, cool, 高对比度} × {默认纸面, 森林样张, 樱花样张（部分覆盖）}——无不可读 / 发脏区域，高对比度下描边可见；
3. 所见即所得与预览排版一致；心流 + 打字机 + 纸面组合回归通过，块级 widget 行号几何零漂移（对照 live-preview-render-fix 断言口径）；
4. 主题包导入校验单测更新全绿（新增两变量的合法 / 非法用例）；旧主题包文件导入不拒（向后兼容）；
5. 导出 PDF / HTML 不吃纸面底色（保持既有印刷白底 / 阅读排版，见设计文档边界节）；
6. 安装包体积增量（字体）实测记录进 CHANGELOG；
7. 每批（P0–P3）发体验包经用户真机验证后进下一批。
