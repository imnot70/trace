# Vim 模式（FR-2.4.23）

> 2026-09-26 立项（用户提案池 [#5](../../suggest/feature-proposals.md) 迁入）。设计文档：待设计；**实施前置：需先拍板键位冲突策略**（见下）。工时评估（建议阶段）★★★☆，2~4 天。

## 需求背景

vim 用户期望编辑器支持 vim 键位（normal / insert / visual 等模式化编辑）。提案阶段已得出关键结论：**插件方案在当前架构下不可行**——插件运行在独立进程，插件 API（命令 / 状态区 / 工具栏声明）没有「编辑器扩展」注入能力，跨进程传 CM extension 会破坏进程隔离设计且工程远大于收益；因此采用**内置实现**，基于官方 `@codemirror/vim` 包集成而非自研。

## 需求

### FR-2.4.23 Vim 编辑模式

- 设置 → 编辑器新增「Vim 编辑模式」开关，**默认关闭**；开启后源码与所见即所得模式均生效（都在 CM 层），心流 / 专注模式下同样可用（vim 用户正是「手不离键盘」的极致用户）；
- 集成 `@codemirror/vim`（normal / visual / insert / replace 完整实现），经既有 Compartment 机制挂载；
- **键位冲突策略（实施前置拍板项，建议方向）**：
  - **Esc**：vim 开启且编辑器聚焦时，Esc 优先让 vim「返回 normal」，全局 Esc 分级回退（关预览 / 收补全 / 退心流）让位——产品约定需在设置页与速查文档明确说明；
  - **Ctrl 系**：逐一决策 vim 的 Ctrl+F（翻页）vs 全局搜索、Ctrl+S（vim 无此键可共存）、Ctrl+N、Ctrl+R（redo）——建议 vim 优先 + 个别键 `unmap` 保应用键位；
  - **Alt 系**（Alt+W / T / F…）：vim 一般不吞带修饰键的组合，实测确认即可；
- **IME 组词**：normal 模式下 IME 禁用（vim 惯例，`@codemirror/vim` 已有处理）；中文输入 + vim 的组合必须真机验证（CDP 测不出，见 [tech_cm6-editor](../../tech/tech_cm6-editor.md)）；
- 补全交互：insert 模式补全正常；normal 模式补全关闭（vim 包既有行为）；
- 设置页开关旁附**冲突速查说明**。

## 验收标准

1. 开关默认关；开启后 normal / insert / visual 基本操作可用，源码与所见即所得两模式一致；
2. 冲突矩阵逐条实测并有结论记录（Esc / Ctrl 系 / Alt 系），应用级键位（保存 / 搜索 / 新建 / 心流）行为符合拍板结论；
3. IME：insert 模式组词正常，normal 模式不误触发输入法（真机验证）；
4. 关闭开关后完全恢复现状（无残留模式、键位无变化）。

## 备注

- 建议先做「最小可用」：开关默认关 + 编辑器内 vim 优先策略 + 冲突速查文档，后续按反馈迭代；
- 真机验证项（IME + 键位手感）依赖 Windows / Linux 真机，排期时预留。
