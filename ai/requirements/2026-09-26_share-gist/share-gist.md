# 分享功能（FR-2.3.10）

> 2026-09-26 立项（用户提案池 [#6](../../suggest/feature-proposals.md) 迁入，按提案建议做一期 Gist）。设计文档：待设计。工时评估（建议阶段）★★，一期 1 天。

## 需求背景

想把笔记生成链接分享给他人。**核心局限（用户指出）**：笔记库可能是 GitHub **private** 仓库——raw 链接带 token 有泄露风险、无权限者 404，不可长期分享。因此分享的本质是**把内容复制到某个公开 / 半公开的载体**，而非「给私有内容一个链接」。第三方 pastebin / 自建服务因隐私与本地优先原则被否决，一期采用 GitHub Gist（复用已登录的 PAT）。

## 需求

### FR-2.3.10 分享为 Gist（一期）

- 笔记 `⋮` 菜单新增「分享…」：用已存储的 GitHub PAT 调 Gist API，把笔记 Markdown 发布为 **secret gist**（有链接即可见、不公开检索）；
- 分享对话框展示生成链接并**一键复制**；同一笔记可**更新**（再推内容到既有 gist）与**删除**（管理既有分享）；
- **PAT scope 前置**：现有 PAT 引导只勾选 repo scope，首次分享时检测并引导用户在 GitHub token 管理页补 **gist scope**（一次性操作，中文分步引导，复用既有引导交互模式）；
- 图片附件不随行（可选 base64 内联，注意 gist 大小限制——设计时定上限与提示）。

### 扩展方向（二期，按需，不立 FR）

- 发布到公开展示仓库：笔记渲染成 HTML（复用导出 HTML 管线）+ 图片一并推到用户指定的 public 展示仓库（如 `<user>/trace-pages`）gh-pages 分支，得到正式发布页 URL；适合「正式发布的笔记页」，需用户自建仓库（★★★，1~2 天）。

## 验收标准

1. 私有库笔记可成功分享为 secret gist，浏览器无登录状态访问链接可见内容；
2. 链接复制可用；再次分享同一笔记可更新内容，对话框可管理（删除）既有分享；
3. 无 gist scope 的 PAT 首次分享触发分步引导，完成后分享成功且后续不再引导；
4. 网络失败 / 超时有中文错误提示（走 errMessage 映射），不泄露 token（日志脱敏）。

## 备注

- 分享记录（gist id ↔ 笔记路径映射）存应用元数据，不写入笔记库（红线：不污染 git 仓库）；
- 待设计问题：gist 描述格式、更新冲突（笔记重命名 / 移动后的关联）、多库同名笔记的消歧。
