## 关键教训与调研结论（本次新增；index §3 已登记的不再展开）

1. **Gist「图片随行」的技术边界**（ share-gist.md 有完整记录）：Gist REST API 文件内容仅收 UTF-8 文本（二进制图片上传必坏）；GitHub 渲染 Markdown 又剥离 `data:` URI（[github/markup#270](https://github.com/github/markup/issues/270)）——即 secret gist + API 发布约束下**无自包含图片方案**。GitHub 官方唯一二进制通道是仓库 **Contents API**（接受 base64），这是二期「公开图床仓库 / 发布页」的可行基础；用户已确认一期用占位文字过渡。
2. **user-guide.md 曾存在未解决的合并冲突标记**（`<<<<<<< HEAD` / `>>>>>>> feature/graphical-conflict-resolution`，随图形化冲突解决分支合入时遗留，本会话才被发现并修复）。教训：**分支合并后对文档目录（尤其 guides/）也要过一遍**，冲突标记会被 `git merge` 成功掩盖。
3. **JsonStore 读取与默认值深合并**：给嵌套默认值（如 `sidebarMenus`）加新键，只需补主进程默认值，老 settings.json 读取时自动回填——无需写迁移。
4. **斜杠命令实现模式**：与 `[[` 补全同挂 `autocompletion({ override: [...] })`，激活区间天然互斥；补全 apply 为函数时**不会自动替换区间**，需在 apply 里先 dispatch 删除「/命令文本」再执行动作，动作必须落到与快捷键相同的既有函数（一致性原则）。
5. gh CLI 已安装但未认证（见环境）。
