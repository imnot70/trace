## 二、待实施：方案 A——垂直移动落点修正，让光标能进入渲染中的块级公式

> 用户已拍板方案 A（体验优先，接受 Vim 侧动 vim 包动作映射的工作量）。**未写任何代码**，本文为完整交接。

### 2.1 现象与根因（已实验定位，2026-09-28）

- **现象**：所见即所得模式下，渲染中的块级公式（多行 `$$…$$` 被替换为 KaTeX widget）是键盘垂直移动的「护城河」——`j` / `k`（Vim）与 `↓` / `↑`（非 Vim）都直接跳过整块（实测：紧排列表内块公式从条目行一步跳到下一条目行，即用户截图的 22→26），公式从不「打回原形」。
- **根因链**（三环缺一不可）：
  1. 块级公式 = CM6 `Decoration.replace({ block: true })` 多行原子区（[decorations.ts](../2026-09-27_typewriter-padding-redesign/) 的 `pushBlock`，`src/renderer/src/lib/livePreview/decorations.ts`）；
  2. 回落条件 = `occupied(state, from, to)`：光标/选区**触碰公式区间（含贴边）**才回落源码（decorations.ts 顶部）；
  3. CM6 垂直移动 `moveVertically`（view 内部）是**纯坐标扫描**（`posAtCoords` 按半个行高步进），扫描点落入块 widget 坐标区时按移动方向返回**远端边界**（向下 → `to`、向上 → `from`）——光标从不触碰区间，回落永不触发。Vim 的 `j`/`k` 经适配层 `findPosV` → `cm6.moveVertically`，与非 Vim 的 `cursorLineDown` 行为完全一致。
- **实验证据**（CDP + DOM 真值，可复现）：松散列表（条目与公式间有空行）`j`：3→4→8；紧排（用户截图同构）`j`：1→5；非 Vim `↓` 同样 4→8。**点击**可进入（点击的 posAtCoords 命中 widget 返回贴边位置 → occupied 触发回落）——非 Vim 用户习惯点击所以缺口不显性；Vim 用户全程键盘故显性。
- **行内公式不受此影响**（已实验证实）：行内 `$…$` 的原子区在一行内，`l`/`h` 走到 `$` 边界即贴边回落（`.lp-math` DOM 计数实测 1→0）。修复时勿动行内路径。

### 2.2 方案 A 设计

**核心函数** `smartVerticalMove(view, dir: 1 | -1)`（建议放 `src/renderer/src/lib/livePreview/` 与装饰模块同处，供 Vim / 非 Vim 共用）：

1. 记录移动前 `head`；
2. 执行默认垂直移动（非 Vim：`cursorLineDown` / `cursorLineUp`；Vim：保持适配层原行为）；
3. **跨块判定**：若移动前后的 head 分居某块级公式区间两侧（`old < from && new > to`，或反向）——即本次移动「飞跃」了该块——把 selection 改为**近端边界**：向下 → `from`（块首行行首），向上 → `to`；
4. dispatch 后 `occupied(贴边)` 自然触发回落，光标落在源码内，行为与 Obsidian 一致。

**区间来源**：decorations.ts 的 `scanBlocks(doc)` 已产出块级公式区间（`mathRanges`，含 from/to）。建议导出一个 `blockMathRanges(state): SimpleRange[]` 供判定复用（或从 StateField value 取，视其结构定）；注意只在 `cfg.enabled`（所见即所得开）时有意义。

**接入点一：非 Vim（简单）**。`MarkdownEditor.vue` 的 keymap（`traceSetup` 或应用级 Prec.high 组）加 `ArrowDown` / `ArrowUp` 绑定，run 内调 `smartVerticalMove`，未跨块时放行默认行为（返回 false 让 defaultKeymap 接管，或直接返回 true——统一在函数内完成）。注意与表格尺寸提示态、`[[` 补全的既有让位规则兼容（提示态最高优先级绑定在前，不受影响）。

**接入点二：Vim（工作量所在，候选按优先序）**：

- **候选 1（推荐先验证）**：`Vim.mapCommand('j', 'action', 'traceSmartDown', {}, { context: 'normal' })` + `Vim.defineAction('traceSmartDown', fn)`（`k` / 上移同理）。action 签名 `(cm, params)`——**需实测**：① 计数（`3j`）是否以 `params.repeat` 传入（是则循环调 smartVerticalMove）；② `context: 'visual'` 的可视模式语义（应为扩展选区：用 `computeSelectionExtension` 或先记 anchor 再 setSelection head）。包内 `mapCommand` / `defineAction` / actionArgs 结构见 `node_modules/@replit/codemirror-vim-core/vim.js`（`mapCommand` 支持额外 `{ context }`；action 类型不走 motion 的 makePos 机制，直接执行函数）。
- **候选 2**：`EditorState.transactionFilter` 全局拦 selection transaction——检测 head 跨块则改写落点。**需实测**：vim 适配层 dispatch 是否带 `userEvent`（不带则无法区分键盘移动与点击 / 拖选，会误伤点击路径）；若实测无 userEvent 则放弃此候选。
- **候选 3（不推荐）**：`Vim.unmap('j'/'k')` + CM keymap 兜底——丢失 vim 计数（3j）与可视模式语义。

**挂载与清理**：候选 1 的 `mapCommand` 是包内全局注册表操作（同 `Vim.unmap` 的全局性），在 `buildVimExtension()` 首次调用时执行一次即可（vimMode.ts 已有 `yieldedKeysRemoved` 同款幂等模式可参照）；建议与 `VIM_YIELDED_KEYS` 并列 `let motionsPatched` 标志。

### 2.3 验收标准

1. 非 Vim：渲染中的块级公式，`↓` 从其上一行能进入源码（回落、光标在块首行），`↑` 从下一行同理；光标离开区间后重渲染（现行为不回归）；
2. Vim：`j` / `k` 同样能进入；**`3j` 计数移动正常**；可视模式（`v` + `j`）选区扩展到块近端不跳块；
3. 点击进入路径不回归（两模式）；行内公式贴边回落不回归；
4. 心流 / 源码模式（所见即所得关）下垂直移动零变化（`smartVerticalMove` 在无块区间时必须等价默认行为）；
5. 单测：跨块判定与近端落点抽纯函数（输入 oldHead / newHead / ranges → 落点），随 `tests/` 既有风格覆盖。

### 2.4 验证方法（本会话已跑通的 CDP 手法）

- 隔离实例：`TRACE_TEST_USERDATA=1 TRACE_CDP=9222 npm run dev`；
- 拿 CM view：`document.querySelector('.editor-pane').__vueParentComponent.setupState.view`；
- 按键注入：页面内合成 `KeyboardEvent`（contentDOM 上 dispatch、bubbles、**必须带 keyCode/which**），CDP `Input.dispatchKeyEvent` 对后台窗口不可靠；
- DOM 真值断言：`.lp-math` 数量（公式渲染 / 回落）、`view.dom.querySelectorAll('.cm-line').length` vs `state.doc.lines`（块渲染时行数差 = 被替换行数）、`doc.lineAt(selection.main.head)`；
- ⚠️ 写测试内容用 `view.dispatch({ changes: … })` 走编辑器管线（`trace.writeNote` 对已打开笔记会静默失败）；侧栏开笔记前要先点库行展开。
