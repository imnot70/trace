# 「手不离键盘」心流动线设计思路（建议存档）

> 2026-09-25 起与用户多轮讨论形成的设计思路存档。其中 P1 / P2 已随 v0.8.6 实施（FR-2.9.10，见 [../2026-09-25_flow-reference-enhance/](../2026-09-25_flow-reference-enhance/flow-reference-enhance.md)），P3 拖曳暂缓待评估。本文档保留设计理念全貌，作为后续心流交互演进的思考基线。

## 一、核心理念

心流模式的价值在「沉浸不中断」，因此引用与速览两类高频动作必须**全程键盘可达**——手离开键盘去摸鼠标的那一刻，心流就断了。设计目标是：

> **两个入口 × 两个动作，覆盖三类场景，全程不离键盘。**

| 场景 | 入口 | 动作 |
| --- | --- | --- |
| 记得笔记名 | `[[` + 名字片段（扁平模糊匹配） | `Enter` 插入引用 / `Alt+Enter` 悬浮预览 |
| 只记得内容 | `Ctrl+F` 搜索 → 关键词 | `↑` / `↓` 选择 → `Enter` 打开 / `Alt+Enter` 悬浮预览 |
| 预览中顺藤摸瓜 | 悬浮预览内点击双链 | 预览内导航（不切走） |

## 二、设计原则（从实现中提炼，后续演进遵守）

1. **入口收敛**：每类动作只有一个漏斗（如 Alt+Enter 唯一入口、Esc 唯一分级回退处理器），新键位挂进既有漏斗而不是旁路；
2. **预览不切走**：「一瞥」语义——悬浮预览展示目标笔记，当前笔记与输入状态原样保留，看完点编辑区 / 插入引用即回；
3. **Esc 分级消费**：预览 → 补全 → 心流三级回退，每级消费按键后阻断下沉，绝不一次退两级；
4. **键盘优先，鼠标对称补充**：拖曳（P3）是给鼠标流的对称能力，属于锦上添花而非必需；
5. **自动补全的括号语义按路径区分**（实现教训）：Enter 接受保留 closeBrackets 的既有闭合；预览态插入整段替换并吸收残留——产出引用必须恰好一对 `[]`。

## 四、P3 拖曳的设计备忘（未实施）

- 编辑器已有 `@drop` 处理（图片）+ CM `dropCursor()`（落点指示线），新增「检测到 `x-trace-note` 类型的 dataTransfer 就在落点插入 `[[引用]]`」是顺路扩展，三个来源共用同一数据格式即可；
- 主要结构性障碍：搜索框是模态对话框，遮罩会挡住 drop 事件——需改非模态或拖起时临时收遮罩（搜索预览的 D3 决策同源）；
- 细节：拖影样式、与图片拖放的分支区分、所见即所得模式下落点插入的一致性。

## 五、相关的既有规则（防再踩）

- 补全打开时 `Ctrl+Enter` 让位给 completionKeymap（接受补全）；行插入用 `Ctrl+Enter` / `Ctrl+Shift+Enter`，二者不冲突；
- 候选项落成引用的括号语义按路径区分（Enter 接受保留既有闭合；预览态插入整段替换并吸收残留 `]]`）——见 FR-2.9.10 四轮记录；
- CM 内置模糊过滤对中文不可靠，wikilink 补全分支已 `filter: false`（源自过滤为准）。
