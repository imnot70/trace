# 编辑位置与文首 / 文尾跳转需求

> 创建：2026-09-24 ｜ 状态：**已实施（已随 v0.8.0 发布）**——实施记录与实测矩阵见 [edit-position_design.md](edit-position_design.md) 第 7 节
> 关联：FR-2.4.4（保存）、FR-2.4.14（打字机）、FR-2.9.8（心流模式）—— 本次新增 FR-2.4.18 / FR-2.4.19
> 本文档记录需求结论（做什么、为什么）；技术方案见 [edit-position_design.md](edit-position_design.md)。

## 1. 背景与目标

现状：打开笔记后光标总在**文首**（与上一次的光标位置也不稳定）。但追加式写作（日记、流水记录、在既有长文末尾续写）恰恰相反——用户希望打开笔记就能**直接在文尾接着写**，省去每次「滚到末尾 / Ctrl+End」。

同时，全尺寸键盘上的 Home / End 键在笔记本（或紧凑键盘）上往往需要 Fn 组合，**主键盘区**缺少一个顺手的「跳到文件头 / 尾」快捷键。

目标：让「打开笔记后光标落在哪里」成为用户可选项（默认保持现状「从头开始」），并补一对主键盘区的文首 / 文尾跳转快捷键。

## 2. 功能需求

### FR-2.4.18 编辑位置（打开笔记后的光标位置）

- **设置项**：设置 → 通用 → 编辑器 →「编辑位置」，取值 `从头开始`（默认）/ `从尾部开始`；描述文案说明作用范围（打开笔记后光标的位置）；
- **生效时机**：打开笔记时（左栏 / 网格卡片 / 收藏 / 常用 / 搜索结果 / 双链跳转 / 重启后恢复上次笔记等所有入口一致）；
- **行为**：
  - `从头开始`：光标落在文首（第 1 行行首），视图滚到文首；
  - `从尾部开始`：光标落在文末（最后一行行尾，通常是文末的空行），视图滚到文末；
- **确定性**：与「上一次编辑该笔记时的光标位置」无关——同一设置下每次打开结果一致；
- **不做**：不记忆「上次编辑位置」（那是另一种语义，见非目标）。

### FR-2.4.19 光标跳转文件头 / 尾（主键盘区快捷键）

- 编辑器内（焦点在编辑器时）：
  - `Ctrl + Shift + H` → 光标跳到**文件开头**；
  - `Ctrl + Shift + E` → 光标跳到**文件末尾**；
- 跳转后视图同步滚动到目标位置（与既有 `Ctrl+Home` / `Ctrl+End` 一致）；
- 源码模式与所见即所得模式均可用；与既有 `Ctrl+Home` / `Ctrl+End` 并存（后者来自编辑器默认键位，不在应用速查表内）；
- 组合键落在主键盘区（字母 H = Head 头部 / E = End 末尾），单手可及。

## 3. 非目标（本期不做）

- **记忆每篇笔记的上次编辑位置**（`rememberLastPosition` 之类）——语义不同（跨会话 / 跨设备噪音大），如需要另行立项；
- 心流模式进入时的光标行为独立化（进入心流不移动光标：位置由「打开笔记」时决定；心流内已有打字机锚定接管视图）；
- 跳转到「上次浏览位置」「书签」「行号跳转」（另属导航能力）；
- 修改 `Ctrl+Home` / `Ctrl+End` 的既有行为。

## 4. 验收标准

1. 设置为 `从头开始`（默认）：打开任意笔记，光标在第 1 行行首、视图在文首；
2. 设置为 `从尾部开始`：打开任意笔记，光标在文末最后一行、视图在文末，直接输入即在文尾续写；
3. 各入口一致生效：左栏树 / 网格卡片 / 收藏 / 常用 / 搜索结果 / 双链跳转 / 重启恢复；
4. 与「上次光标位置」无关：先在笔记 A 中间停留，再打开笔记 B，B 的位置依旧按设置决定；
5. 重命名笔记、外部修改重载（git 同步 / 外部编辑）**不触发**光标跳转（用户正在编辑的内容与光标不应被打断）；
6. `Ctrl + Shift + H` / `Ctrl + Shift + E` 在源码与所见即所得两种模式下均把光标移到文首 / 文尾并滚动到位；
7. 既有快捷键不回归：`Ctrl+E`（切换编辑模式）不受影响；`Ctrl+Home` / `Ctrl+End` 仍可用；
8. 设置项持久化（重启后保持），非法值回退默认；既有单元测试不回归。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 默认值改变既有习惯 | 默认 `从头开始`＝现状行为，升级后无感 |
| 「从尾部开始」打开超长笔记时滚动到文末带来"跳"的观感 | 打开笔记本身就是上下文切换，滚到文末是预期；心流 / 打字机模式下由锚定规则接管，观感一致 |
| 与其他「打开后跳转」的能力冲突（搜索结果定位到匹配行） | 定位类能力只做滚动、不设光标；本次只在打开瞬间设置一次光标，随后的定位滚动照常生效 |
| 快捷键与既有键位冲突 | `Ctrl+Shift+H` / `Ctrl+Shift+E` 在编辑器默认键位、应用全局键中均未占用；唯一冲突点 `Ctrl+Shift+E` 与全局 `Ctrl+E`（切换编辑模式）的判定过宽，需一并收紧（详见设计文档 D4） |
