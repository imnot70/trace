## 关键技术细节与坑

1. **IPC 返回值必须显式给对象**：`RecentsService.remove()` 返回 `void`，IPC handler 原样透传会令渲染端拿到 `undefined`，但 `TraceApi` 类型声明是 `Promise<OpResult>`，**typecheck 拦不住**——运行时访问 `result.ok` 抛错。修复：handler 内显式 `return { ok: true }`（参考 `recent:add` 的写法）。新增 IPC 通道时一律照此模式。
2. **`readNote` 的 `content` 是可选字段**（`NoteContent` 非判别联合），`result.ok` 不收窄类型，取值前需 `result.ok && result.content != null`。
3. **网格卡片单击/双击区分**：单击用 220ms 计时器延迟执行，`dblclick` 时清除计时器再进编辑；双击的第二次 click 直接忽略。
4. **网格视图与编辑器互斥**：`app.view = { name: 'grid', section }` 时 `EditorView` 整体不挂载（预览卡自然消失且不动 `previewVisible` 持久化偏好）。悬浮预览在网格内是独立实现（读取 `readNote` 内容渲染 `MarkdownPreview`），不依赖 editor store。
5. **摘要加载有竞态保护**：`NoteGridView` 用递增 `excerptSeq` 丢弃过期读取结果；列表变化（收藏/取消/删除）通过 watch 自动重载，无需手动刷新。
6. **「移出常用」左上角闪影（已修复，两阶段）**：点击后刷新列表会移除 ⋮ 菜单的锚点行，Element Plus 下拉 popper（teleport 到 body）在收起动画中失去锚点，floating-ui 对分离元素算出全零 rect，popper 带阴影闪到视口 (0,0)。属时序竞态（用户录屏证实第二次点击仍复现）。**最终方案**：① 侧栏「常用 / 收藏」改为语雀式单行入口（行内列表整体移除，锚点行场景不复存在）；② `NoteGridView.onMenuCommand` 对会移除卡片的操作（移出常用、收藏区取消收藏）先等 350ms 收起动画再执行（`actions.removeRecent` 不再内置延迟）。「删除笔记」有确认弹窗不需要保护。**通用规则：今后任何「点击后立即移除下拉菜单锚点元素」的菜单项都需要此类保护。**排查方法：`TRACE_CDP=9222 TRACE_TEST_USERDATA=1 npm run dev` + playwright `connectOverCDP` 驱动 UI（脚本须 try/finally 清理并恢复默认工作区；TaskStop 只杀外壳，electron/vite 子进程会残留占端口，需按 PID 树杀；窗口被遮挡时 rAF 节流到 1Hz，须先激活窗口；⚠️ 自动化期间用户若手动操作同一窗口会互相干扰）。

## 本机环境注意事项（Windows 开发机）

- **git 集成测试会假失败**：`tests/gitService.test.ts` 的 6 项集成测试在 Windows 上因 git 子进程启动开销（每次约 1~1.7s，Linux 仅几十 ms）超出 Vitest 默认 5s 超时。功能正常，用 `npx vitest run --testTimeout=30000` 验证，勿误判为代码 bug。
- `npm run lint` 整体跑会报错：`lint` 脚本里的 `scripts` 目录被 ESLint 配置完全忽略（既有问题）。单独 lint 改动文件即可；要根治可从 lint 脚本去掉 `scripts`。
