# 项目需求

## 项目简述
这是一个轻量级的笔记软件项目。
主要支持平台：Windows、Mac、Linux，其中Linux以Ubuntu及Debian系为主。
主要支持的特性：
- 同步git仓库
- 文件内容以markdown文件保存
- 支持Latex
- 支持插件功能
- 支持主题功能

## 文件结构
用户可以按主题创建“笔记库”（即最顶层目录），“笔记库”下可以再创建多子目录，子目录可以多级创建，最下层内容为“笔记”（即markdown文件）
大致结构图：
```plaintext
-笔记库1
 |-一级子目录1
   |-一级子目录1的笔记1
   |-一级子目录1的笔记2
 |-一级子目录2
   |-二级子目录1
    |-二级子目录1的笔记1
    |-二级子目录1的笔记2
 ...
```
## UI设计
UI采用左右分栏的设计，左侧边栏主要是菜单功能。从上至下分别是
- 常用
- 收藏
- 回收站
- 笔记库
除了上面的三个菜单，在左边栏的左下角设计一个小齿轮，这是“设置按钮”，里面可以进行登录（登录git账号），插件管理，和系统设置
这里可以参考images/main-ui.jpeg

## 主要功能
### 笔记库管理
- 创建笔记库，用户可以按主题创建笔记库，创建时需要用户输入笔记库的名称，系统需要检查名称是否与已有的笔记库重名。创建好的笔记库会列出在左侧的笔记库菜单中，同时笔记库的名字右侧会有一个设置按钮（用小齿轮表示）和一个加号按钮，其中设置按钮提供以下功能：
    - 关联git仓库（如果用户没有登录github账号则提示用户需要登录github）
    - 重命名
    - 删除笔记库
加号按钮提供以下功能：
    - 创建子目录
    - 创建笔记
- 笔记库重命名，在笔记库设置按钮中提供的功能，用于修改笔记库的名字，重命名时需要检查是否和已有的笔记库重名
- 删除笔记库，在笔记库设置按钮中提供的功能，删除的笔记库和库中的内容会被放入回收站（可以通过左侧栏的回收站查看已经删除的库），如果笔记库中有内容（子目录或笔记文件）则提示笔记库中的内容会被一起删除。
- 创建子目录，可以创建子目录。具体见子目录管理中的创建子目录功能
- 创建笔记，可以创建笔记文件。具体见笔记管理中的创建笔记功能

### 子目录管理
- 创建子目录，笔记库下可以创建子目录，创建时用户需要输入目录名称，系统需要检查名称是否与当前目录/库下已有的目录重名。子目录的名字右侧会有一个设置按钮（这里使用三个点表示）和一个加号按钮，其中设置按钮提供以下功能
    - 重命名
    - 删除子目录
加号按钮提供以下功能：
    - 创建子目录
    - 创建笔记
- 子目录重命名，在子目录设置按钮中提供的功能，用于修改子目录的名字，类似库的重命名，需要检查是否重名
- 删除子目录，在子目录设置按钮中提供的功能，删除的子目录和子目录中的内容会被放入回收站。如果子目录中有内容（次级的子目录或笔记文件）则提示子目录中的内容会被一起删除。
- 创建子目录，子目录中可以再创建子目录，目前先限制为最多6层（不算最顶层的笔记库）。第6层子目录再创建子目录则提示“已达最大层数”
- 创建笔记，可以创建笔记文件。具体见笔记管理中的创建笔记功能

### 笔记管理
- 创建笔记，库和子目录下可以创建笔记文件，创建笔记文件后用户需要输入笔记名称，系统需要检查名称是否与当前路径下的笔记重名。笔记名的右侧会有一个设置按钮（用三个点表示），设置按钮提供以下功能：
    - 重命名
    - 删除笔记
    - 收藏笔记
- 重命名，修改笔记的名字，需要检查是否重名
- 删除笔记，删除前会弹出确认窗口，用户确认后再把文件移动到回收站
- 收藏笔记，收藏后的笔记会添加到左侧的收藏目录下
- 编辑笔记内容，允许用户对当前笔记内容进行编辑，需要支持以下内容：
    - Markdown格式内容
    - Latex格式内容

这是目前的需求，我们先按这个方向讨论需求。明确细节

# 补充需求（v0.1.0 实现过程中追加）

> 用语说明：自 v0.1.0 起，界面操作统一使用「文件夹」指代原需求中的「文件夹」。

> 以下为原需求未覆盖、在开发讨论中确认或实现过程中补充的设计与功能，按当前实现如实记录，供后续整理进正式需求。

## 一、总体设计约定

- 应用名 Trace，中文名「笔迹」。
- 技术栈：Electron + Vue 3 + TypeScript + Pinia + Element Plus；编辑器 CodeMirror 6；Markdown 渲染 markdown-it，公式渲染 KaTeX（`$...$` 行内、`$$...$$` 块级），代码高亮 highlight.js；git 操作基于系统 git（需已安装，缺失时仅同步功能不可用，其余功能正常）。
- 数据以本地文件为唯一事实来源：
  - 存在一个全局「工作区根目录」（默认 `~/Trace`，可在设置中更换）；
  - 每个笔记库 = 工作区根目录下的同名文件夹，同时是一个独立 git 仓库（未关联远端即纯本地库）；
  - 应用自身元数据（设置、收藏、最近打开、GitHub 凭据、已装插件）存放在系统应用数据目录（Linux 为 `~/.config/Trace/`），不写入笔记库，避免污染 git 仓库。
- 应用单实例运行；应用菜单中文化；外部链接用系统浏览器打开。

## 二、名称与校验规则

- 笔记名即文件名（创建时自动补 `.md`），界面显示时去掉 `.md`。
- 名称不可包含：`\` `/` `:` `*` `?` `"` `<` `>` `|` 及控制字符；不可以点开头或结尾；不可使用 Windows 保留名（CON、PRN、AUX、NUL、COM1-9、LPT1-9）；长度上限 100 字符。
- 重名校验大小写不敏感（兼容 macOS / Windows 大小写不敏感文件系统）：笔记库之间全局唯一；文件夹 / 笔记在同一父目录内唯一。
- 文件夹深度上限 6 层（不含笔记库本身），超限提示「已达最大层数」。

## 三、笔记编辑（细化）

- 编辑器形态：左侧源码编辑 + 右侧实时预览，中间分隔条可拖拽调整比例，滚动按比例联动。
- 编辑工具栏：撤销、重做、加粗、斜体、删除线、H1/H2、引用、行内代码、代码块、链接、行内公式、公式块（原应用菜单中的编辑操作已内嵌于此，应用不再显示原生菜单栏）。
- 界面整体为卡片式布局：灰色画布上浮三张圆角卡片——左侧栏、编辑卡片（面包屑 + 工具栏 + 编辑器合并其中）、预览卡片，间距统一 10px，分隔条为透明间隙、悬停时显示细条。
- 预览卡片可收缩：编辑卡片顶栏有「隐藏/显示预览」按钮，状态持久化（localStorage），下次启动保持。
- 专注模式（Zen）：编辑卡片顶栏与左侧栏底部均有「四角方框」按钮，开启后隐藏侧栏与预览，只保留编辑卡片；再次点击退出。入口仅在编辑视图显示，避免无法退出。
- 自动保存：编辑后 1 秒防抖写盘（设置中可关闭）；`Ctrl+S` / `Cmd+S` 手动保存。
- 外部修改检测：以磁盘内容 hash 比对代替时间戳。文件被外部修改后：
  - 本地无未保存改动 → 静默重载；
  - 本地有未保存改动 → 顶部横幅提示，可选择「放弃本地修改并重载」或「保留本地修改继续编辑」；若强行保存会被拒绝，防止覆盖。
- 文件监听：库内文件被外部增删改（git 拉取、其他编辑器）时，侧栏树与 git 状态自动刷新（git 同步操作期间监听挂起，避免自我触发）。

## 四、图片 / 附件

- 支持粘贴、拖入图片，自动保存到库内附件目录，文件名加时间戳前缀防重名。
- 附件目录可配置（设置 → 通用 → 附件目录）：相对于笔记库根目录，支持多级（如 `media/image`，最多 4 层）；修改后只对之后粘贴的图片生效，已有图片的引用不受影响。默认 `attachments`。
- 笔记中插入相对路径引用；预览通过自定义协议 `trace-vault://<库名>/<库内路径>` 加载显示。

## 五、收藏与常用

- 收藏：按「库名 + 库内路径」引用；笔记重命名 / 父目录或整个库移动删除时自动跟随更新或清理失效条目。
- 常用：最近打开的笔记，按打开时间倒序，上限 20 条。
- 两者均为应用级元数据，不随 git 同步。

## 六、回收站（细化）

- 应用级回收站，位于工作区根目录 `.trash/`（不进入任何 git 仓库）；索引记录原位置、类型、删除时间。
- 库 / 文件夹 / 笔记的删除统一进入回收站。
- 支持单条还原（原位置已存在同名对象时自动追加「（已恢复）」后缀，不覆盖）、单条彻底删除、一键清空。
- 回收站提供列表视图：名称、类型（笔记库/文件夹/笔记）、原位置、删除时间、操作；删除类操作在菜单中以红色字体警示。

## 七、Git 同步（详细语义）

- 账号登录：设置 → 账号，粘贴 GitHub Personal Access Token（需仓库读写权限）。令牌经系统加密存储（Electron safeStorage；Linux 无 libsecret 时降级明文并记录警告）。支持退出登录。
- 关联远程仓库：库齿轮菜单 →「关联 Git 仓库」；未登录时弹窗引导先去登录。支持从账号下仓库列表选择（可搜索）或直接新建仓库（可设公私有）。
- 首次同步策略：远端有内容且本地为空 → 采用远端历史；远端为空 → 推送本地内容；两边都有 → rebase 合并。
- 日常同步（库菜单「立即同步」/ 编辑页「同步」按钮）：提交本地全部变更 → rebase 拉取远端 → 推送。
- 冲突处理：rebase 冲突时自动中止，弹窗列出冲突文件，本地工作区内容保持不变，由用户手动解决（v1 无图形化冲突解决）。
- 解除关联：移除 origin 远端，保留本地全部提交历史。
- 安全约定：令牌仅在每次 git 调用时经 `http.extraheader` 注入，绝不写入 `.git/config`；日志统一脱敏；提交作者优先使用登录用户名（`<user>@users.noreply.github.com`），未登录时使用 Trace 占位身份。
- 库内自动设置 `core.quotepath false`，保证中文文件名显示正常。
- 状态展示：库行显示关联徽标，编辑页显示分支名、未推送 ↑ / 未拉取 ↓ 数量、有无未提交修改。

## 八、主题

- 全部界面颜色基于 CSS 变量；内置浅色 / 深色 / 跟随系统三种模式，设置页即时切换。
- 预留自定义主题能力（主题即一组 CSS 变量覆盖文件）。

## 九、系统设置

- 工作区根目录更换（目录选择器 + 应用，生效后刷新全部数据并关闭已打开笔记）。
- 主题切换、编辑器字号（12–22px）、自动保存开关。
- 插件管理与「启用插件」总开关。
- 关于信息（应用版本）。

## 十、插件系统（v1 骨架）

- 插件放置于应用数据目录 `plugins/<id>/`，须含 `manifest.json`（id、name、version、description、main 入口、permissions 权限声明）。
- 加载器：仅当设置开启「启用插件」且该插件被启用时，才执行入口文件的 `activate(ctx)`；`ctx` 提供 `notify(message)`（向用户弹通知）与 `logger`；`activate` 返回的函数将作为停用回调。
- 首次运行自动复制示例插件（`resources/sample-plugin/`）到插件目录，作为开发模板。
- v1 不开放第三方插件市场与完整扩展 API。

## 十一、其他实现约定

- 应用图标由脚本生成（`scripts/generate-icon.js`，纯 Node 实现 PNG 编码，`npm run icon` 重新生成）。
- 打包：electron-builder；Linux 产出 deb + AppImage，Windows 产出 NSIS 安装包，macOS 产出 DMG。
- 质量配套：Vitest 单元测试（含用本地 bare 仓库模拟远端的 git 同步 / 冲突集成测试）、ESLint + Prettier、双端（主进程 / 渲染进程）独立 typecheck。

## 十二、已知局限与二期规划

已知局限：
- 列表项内的块级公式（`- $$...$$`）渲染不理想（markdown-it-texmath 的局限）。
- 回收站不感知容量，不自动清理过期条目。

二期候选（v1 未做）：
- 全局搜索
- 所见即所得编辑模式（与源码模式可切换）
- 图形化冲突解决
- 变更 / 定时触发的自动同步
- 自定义主题包导入
- 插件完整 API 与市场
- 标签系统、多窗口
- 导出 PDF / HTML
