# 编辑器工具（折叠按钮 / 标题层级 / 表格插入）需求

> 创建：2026-09-24 ｜ 状态：**已实施（已随 v0.8.0 发布）**——实施记录见 [editor-tools_design.md](editor-tools_design.md) 第 7 节
> 关联：FR-2.4.3（工具栏）—— 本次新增 FR-2.4.15 / FR-2.4.16 / FR-2.4.17
> 本文档记录需求结论（做什么、为什么）；技术方案见 [editor-tools_design.md](editor-tools_design.md)。

## 1. 背景与目标

三处编辑器体验短板（2026-09-24 用户实测反馈）：

1. **折叠按钮太小、样式不搭**：层级 / 块内容折叠按钮（行号列右侧的折叠箭头）尺寸偏小、字形纤细，与应用的 Element Plus 图标语言不一致，热区也偏小、不易点中；
2. **标题没有快捷键**：工具栏只有 H1 / H2 两个直按按钮，三级以下标题只能手写 `###`，且没有任何标题层级快捷键（同类编辑器普遍支持 `Ctrl+1`–`Ctrl+6`）；
3. **插入表格没有入口**：工具栏没有表格按钮，也没有快捷键，用户只能手写 GFM 表格语法。

目标：在不改变「文件是纯 Markdown」的前提下，让上述三类高频结构操作都有称手的入口。

## 2. 功能需求

### FR-F1 折叠按钮（层级 / 块内容）优化

- **视觉**：折叠 / 展开箭头使用与应用一致的图标语言（线性箭头图标，尺寸约 16px），常态次级色，悬停时获得圆角背景与正文色（与侧栏折叠箭头、迷你导航条同语言）；
- **热区**：可点击区域不小于 20×20px（当前约 18px 宽、字形更小）；
- **行为不变**：折叠范围与快捷键沿用 CM 既有能力（标题层级、引用、代码块、HTML 块、表格），折叠后的占位符样式保持现状；
- 不引入新的折叠语义（不做「按标题层级折叠全部」等额外功能）。

### FR-2.4.15 标题层级快捷键

- 编辑器内（焦点在编辑器时）`Ctrl+1` … `Ctrl+6` 将**当前行**设为对应级别标题（`#` … `######`）；
- **清除标题**：`Ctrl+0` 去掉当前行的标题标记（任意级别）；
- **开关语义**：若当前行已是该级别标题，则按一次**去掉**标题标记（再次按恢复）；
- **多行选择**：选中多行时，对选区覆盖的每一行生效（逐行套用同一级别）；
- **工具栏**：原 H1 / H2 两个直按按钮升级为「标题」下拉菜单（一级 ~ 六级，含快捷键提示），使六个级别在工具栏**同等可达**；
- 不改动现有 `Alt+1..4`（视图切换）等键位分层；`Ctrl+数字` 此前无占用。

### FR-2.4.16 表格插入

> 本节记录**首版交互**（`Ctrl+T` 直接插入固定模板）。2026-09-24 后续迭代已改为「先弹尺寸输入提示浮层、再按尺寸插入」，见 [2026-09-24_table-insert-enhance/](../2026-09-24_table-insert-enhance/table-insert-enhance.md)（FR-2.4.20 / FR-2.4.21）。

- **工具栏**：新增「表格」按钮，插入默认模板（2 列表头 + 1 行空数据行）：
  ```
  | 列 1 | 列 2 |
  | --- | --- |
  |  |  |
  ```
- **快捷键**：`Ctrl+T`；
- **插入语义**：在光标处插入；若光标所在行此前已有内容（非空白起始），先换行再插入，保证表格独占行块；插入后光标落在首列表头单元格内（便于直接改名）；表格文本后补一个换行，便于继续书写；
- 不触碰预览与导出：插入的即标准 GFM 表格，既有渲染管道照常生效。

## 3. 非目标（本期不做）

- 表格的可视化编辑（增删行列、拖拽列宽、对齐按钮等）——首版只解决「插入」；
- 表格行列数选择面板（首版固定 2×1，可后续在菜单中扩展 3×3 等预设）；
- 折叠范围的扩展（如「折叠全部」命令、记忆折叠状态）；
- 编辑器输入法的其它改动。

## 4. 验收标准

1. 折叠按钮：箭头为 16px 线性图标、常态次级色、悬停有圆角背景；可点击区域 ≥20×20px；点击行为（折叠 / 展开）与现状一致，折叠后显示既有「⋯」占位符；
2. 折叠标记出现的场景与现状一致（标题、引用、代码块、HTML 块、表格）；
3. `Ctrl+1`…`Ctrl+6` 在源码模式与所见即所得模式下均生效；对已是同级标题的行再按一次即去掉标记；`Ctrl+0` 清除任意级别的标题标记；多行选择逐行生效；操作可单步撤销；
4. 工具栏「标题」下拉在六个级别间切换正确，下拉中显示对应快捷键；下拉不遮挡、不闪影（遵循仓库既有的下拉 / tooltip 约束）；
5. `Ctrl+T` 与工具栏「表格」按钮均在光标处插入模板；行中插入时表格独占行块；插入后光标位于首列表头单元格；模板渲染为正确表格（预览与所见即所得一致）；
6. 所有插入操作可撤销（`Ctrl+Z` 单步回退）；
7. 既有单元测试不回归；新增「标题前缀计算」与「表格模板与插入位置计算」的纯函数单元测试；
8. 磁盘产物仍为纯 Markdown，无任何私有格式。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 替换 `basicSetup` 为自有装配会误伤既有编辑器行为（丢扩展 / 丢键位） | 装配清单与 `basicSetup` 逐项对齐，仅替换折叠按钮一项；实施后用「基础编辑能力清单」逐项冒烟（撤销、搜索、括号配对、补全、多选） |
| `Ctrl+数字` 与系统 / 浏览器快捷键冲突 | Electron 内 `Ctrl+1..6` 无系统级占用（`Alt+1..4` 才是本应用的视图切换）；在编辑器外（焦点不在编辑器）不响应，避免影响全局 |
| 表格快捷键 `Ctrl+T` 与既有键位冲突 | 已核对 CM 默认键位表（`defaultKeymap` / `searchKeymap` / `historyKeymap` / `foldKeymap` / `completionKeymap`）与应用全局键（`App.vue`）均未占用 `Mod-t` |
| 工具栏下拉与既有 tooltip 约束冲突（AGENTS.md：tooltip 禁止包裹下拉触发器） | 下拉触发按钮使用原生 `title`，不使用 `el-tooltip`；沿用仓库既有的 `menu-hold` / `dd-instant-hide` 下拉模式 |
| 标题前缀改写破坏行首缩进 / 列表内的伪标题 | 只识别行首 `#{1,6}` 前缀（可含少量前导空格），不触碰其它结构；单测覆盖多行、已是目标级别、含前导空格等边界 |
