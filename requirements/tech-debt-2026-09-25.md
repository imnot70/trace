## 〇、总体结论

**架构骨架是健康的，没有结构性腐烂**：

- 三进程隔离（主进程独占 fs/git/网络）、类型化 IPC（preload 与 `shared/api.ts` 编译期锚定，88 个方法一一对应）、「文件是唯一事实来源」贯彻彻底；
- 领域服务构造注入、装配集中在 `main/index.ts`，无服务私自 import 他服务内部函数的情况；
- TypeScript 质量优秀：渲染端 12.5k 行中 `@ts-ignore` / `@ts-expect-error` = 0，`: any` 仅 6 处，`as any` = 0；
- `lib/livePreview/` 是深模块范本：纯函数计算核心 + 渲染 widget + 装配三层分离，0 次 `window.trace`、0 次 store 引用，可单测（已有 tests/livePreview.test.ts）；
- 插件系统（pluginHost/pluginGateway，~1.5k 行）是主进程设计最好的部分：判别联合 RPC 协议、超时/背压/崩溃守护完整、权限检查收口在纯函数 `dispatchCapabilityCall`（可单测）。

问题集中在三类：**① 评审新核实的缺陷**（§二，含 1 个安全洞与 2 个真 bug）；**② 视图层随功能堆积开始失控**（§三）；**③ 地基薄点**——持久化无版本迁移、索引生命周期不完整、UI 层零测试（§二.7 / §四）。

技术选型本身几乎全对（§一），可改进的主要是选型**周边的接缝**，而非选型本身。

## 二、已核实的缺陷（待修清单）

> 均已同步 index.md 第二节。①②③ 建议优先。

### 1. 冲突解决接口存在路径穿越（安全，P0）

- **证据**：`src/main/services/gitService.ts` `resolveConflict` 内 `const fullPath = path.join(vaultPath, filePath)` 直接写盘 + `git.add(filePath)`，`filePath` 来自渲染端 IPC 参数，**未过 `resolveWithin` 校验**。`resolveWithin` 就在 `lib/paths.ts`，fsTree / vaults 均在用，唯独此处漏了。
- **影响**：渲染进程被攻破（或插件经 XSS 类向量）时可借 `../` 越权写任意文件。「渲染进程不直接触碰文件系统」的边界承诺在此处破缺。
- **修法**：1 行——与 fsTree/vaults 同款 `resolveWithin` 校验后放行。

### 2. 从搜索结果打开笔记会污染「常用」列表（功能，P1）

- **证据**：`src/renderer/src/App.vue:42` 调 `editor.openNote(vault, path, result.content)`，把**整篇笔记内容**传进 `name`（显示名）参数（签名 `stores/editor.ts:46`，第三参用于 `addRecent` 持久化）。常用网格卡片标题渲染 `item.name`（`NoteGridView.vue:533`）——即常用列表里该条目的标题会变成整篇笔记内容。
- **连带**：`openNote` 内部会重读文件（`readNote`），App.vue 预先读一次纯属多余；这是绕过 `composables/actions.ts` 统一入口的直接代价（其余调用点——VaultNode、BacklinkPanel、actions——都传对了显示名）。
- **修法**：改走 `actions.openNote(vault, path, 显示名)` 或传 `path` 叶子名；删掉多余的 `readNote`。

### 3. 搜索索引不随文件变更更新（功能，P1）

- **证据**：watcher → 索引链只接了双链索引（`main/index.ts:344-358` 的变更回调调 `wikilink.updateFileIndex`），**search 完全不在链上**；主进程仅在启动（`index.ts:392`）与手动重建（`SearchDialog.vue:311`）时全量重建。渲染端 `stores/search.ts:97-110` 的 `updateFileIndex` / `removeFileIndex` 与主进程 `search:updateFile` / `search:removeFile` 两个 handler（`registerIpc.ts:637/646`）是**无人调用的死代码**（全仓 grep 确认无调用方）。
- **影响**：两次重建之间索引陈旧——新建 / 重命名 / 外部修改 / git 同步拉取的文件搜不到、已删文件仍能搜出。
- **修法**：随「搜索支持标签维度」立项一并重构（见 §六.2）：索引挂上 watcher 增量链 + 换轻量索引库（如 minisearch）+ frontmatter 标签结构化提取；或反向收敛——删掉死链路、把「手动重建」改为「重建 + 每次打开搜索框时静默重建」。

### 4. `settings:set` 无白名单合并（加固，P2）

- **证据**：`src/main/services/settings.ts:14` `update()` 用 `Object.assign(s, patch)` 直接把渲染端任意 patch 合入设置并持久化，键无白名单。
- **影响**：本地应用低危，但破坏「设置键是封闭集合」的约束；升级换名后幽灵键永远留在 settings.json。
- **修法**：按 `AppSettings` 键集合过滤，或逐键 setter。

### 5. git 同步无按库互斥（加固，P2）

- **证据**：手动 `git:sync`（`registerIpc.ts:284`）与 autoSync tick（`autoSync.ts:96-101`）可并发对同一仓库执行同步，`gitService` 无任何互斥。
- **影响**：撞 `.git/index.lock` 时把内部错误文案直接暴露给用户。
- **修法**：gitService 内按 vault 加互斥（Map<vault, Promise> 串行化），后到者等待或静默跳过（autoSync 场景跳过更合理）。

### 6. watcher 通知链两处缺口（加固，P2）

- **补偿缺口**：git 同步期间（`suspendDepth > 0`）文件事件直接丢弃（`watcher.ts:40-43`），恢复后只补偿重建**双链**索引（`watcher.ts:76-79`、`index.ts:356-357`），**不重发 `fs:changed` 也不刷新搜索**——同步拉取一批文件后渲染端目录树/编辑器可能保持陈旧。
- **防抖无上限**：聚合按 vault 400ms 尾沿防抖（`watcher.ts:96-106`），无最大等待上限，持续写入会无限推迟通知；且事件类别被聚合丢弃（add/unlink/change 不分），渲染端只能全量重扫树（`tree.ts:121`）。
- **修法**：resume 补偿改为「重建双链索引 + 重发一次 fs:changed」；防抖加 max-wait（如 2s 强制触发）。

### 7. JSON 持久化地基（加固，P2）

`lib/jsonStore.ts` 是 favorites / recents / settings / 插件权限记录 / vaultMeta 等所有应用元数据的底座，有四个薄点：

- **无 schema 版本与迁移机制**：迁移散落 3 处 ad-hoc（`index.ts:193-200` 音色、`index.ts:370-373` autoSyncMode、`tags.ts:131-156` 旧标签元数据），每加一处都要手写一遍。
- **浅合并丢嵌套默认键**：`load()` 是 `{ ...defaults, ...parsed }`（`jsonStore.ts:15-22`），新版本给**嵌套**默认值加键会被旧数据整体顶掉——真实的升级 bug 面（`sidebarMenus` 这类嵌套结构已踩在此雷区上）。
- **损坏静默回退**：JSON 解析失败直接回退 defaults（无提示、无备份），favorites / 回收站索引损坏即无感丢数据。
- **写盘质量**：tmp + renameSync 原子，但无 fsync（崩溃时 rename 后内容不保证落盘）；每次 `update()` 在主线程同步全量重写（recents 每次打开笔记都写盘）。
- **顺带**：插件权限记录混在 settings.json（`index.ts:176-177`），应拆独立文件。

**修法**：`JsonStore` 加 `schemaVersion` 字段 + `migrate()` 钩子 + 深合并 + 损坏时保留 `.bak`；散落迁移收进去。趁数据文件还少赶紧做，越晚迁移越难写。

### 8. 小项（攒批处理）

- **双链正则不避代码块**：`wikilink.ts:37` 的 `WIKILINK_RE` 逐行扫描无代码围栏状态跟踪，代码块里的 `[[xxx]]` 会被当真引用，进入断链列表造成误报。
- **死通道**：`export:resetDir` 注册于 `registerIpc.ts:459` 但 preload 未暴露，渲染端无法触达。
- **`continueRebase` 错误串**：`gitService.ts:415` 把原始 `${e}` 拼进错误串，绕过了 errMessage 中文映射。
- **PAT 残余风险（接受现状）**：token 经 `-c http.…extraheader` 出现在 git 子进程 argv（/proc 可见），且对本地无网命令也无谓注入。可优化为仅在远端命令时注入；现状风险可接受，登记备查。

## 三、架构改进项（随功能顺路，不专门立项）

### 渲染端

1. **SettingsView 拆分**（第一刀）：1455 行承载 8 个功能域——账号 / 工作区与附件 / 代理 / 主题导入 / 插件管理 / 插件市场 / 插件包导入 / 插件详情卸载，仅插件域就近 500 行 + 15 次裸 IPC。拆出 `PluginSettings` 子组件 + `stores/plugin.ts`，设置页可降到 ~900 行。
2. **IPC 访问纪律**：全仓 120 次 `window.trace` 散布 22 个文件，其中 52+ 次在视图/组件裸调（SettingsView 15、actions 13、App.vue 8、SideBar 7……）。约定：**视图/组件只走 store 或 composables，store 是唯一 IPC 门面**（`stores/editor.ts` 已是范本）。§二.2 的 App.vue bug 就是纪律缺失的直接代价。优先收口：SideBar 标签 CRUD（`:123-183` → tags store）、断链引用双份 fetch（SideBar 与 NoteGridView 各自独立请求）、NoteGridView 的 5 次裸调。
3. **store 依赖理顺**：`app.ts:3` ↔ `tree.ts:3` 模块级循环 import（根源是「位置上下文 lastLocation」在 app/tree/editor 间来回写，应收敛单一所有者）；`useRemoteRepos` 藏在 `stores/trash.ts:48-75`（GitAssociateDialog 从 trash 导入，纯归置错误）；git store 里塞着对话框状态（`conflictResolution`）与 ElMessageBox 引导流程，应下沉 actions 层。
4. **重复代码**：NoteGridView `onFolderMenuCommand`（`:236-256`）绕开 actions 层重写了一遍文件夹导出级联（与 `actions.ts:251-284` 重复）；slugify 在 `lib/markdown.ts:192-197` 与 `MarkdownEditor.vue:196-198` 各一份；actions 的 `refreshVault + loadFavorites + loadRecents` 级联重复 6 次、`exportFolder` 与 `exportFolderMergePdf` 的 collect 闭包整段复制。
5. **lib 层越界**：`lib/wikilink.ts` import Vue 的 `h` + ElMessage/ElMessageBox 并直调 `window.trace`（`:3-4, :23`）——对话框流程混进 lib 层，应降级为 composable；`lib/markdown.ts` 对 texmath 内部结构有 3 处 `as unknown as` 猴补（`:70-71,91`），升级 markdown-it 时脆弱。

### 主进程

1. **级联编排下沉领域服务**：rename/delete 的跨服务级联（双链改写、收藏、最近打开）写在 IPC 层（`registerIpc.ts:115-172`），且 `fsTree` 靠 setter 注入 wikilinkService（`fsTree.ts:28-39`）——未来任何新入口（插件 API、导入向导）都要记得复刻这套级联，漏一处就是静默数据不一致。应下沉为领域服务，IPC 与未来入口共用。
2. **registerIpc 拆分**：695 行单函数靠注释分节；下半段（git 冲突 / search / wikilink）又各自重复 try/catch，应统一收敛到 `handle()` 包装器；按域拆文件。
3. **handler 签名类型锚**：preload 侧有 `const api: TraceApi` 编译期锚定，主进程 handler 签名无对应锚——IPC 链条上唯一未闭合的一环（channel 名三处手写裸字符串）。
4. **日志覆盖补齐**：fsTree / vaults / favorites 全静默，出错只能靠 IPC 层兜底日志（`registerIpc.ts:76`）。
5. **保存回声抑制机制**：主进程 watcher 不区分写入来源，靠渲染端重读磁盘内容与 `_diskContent` 比对判定自身保存回声（`editor.ts:121-139`）——依赖读盘时序，且每次自动保存多一次 IPC 往返。可用可文档化；若将来出问题再考虑写入方打标。

## 四、测试策略补强

- **现状**：348 项单测 + 主/渲染双 typecheck 覆盖全部主进程服务与渲染 lib 层（强项）；**CM6 集成层（视图/组件）零测试**——而近年所有 P0 回归（键位 preventDefault、行号几何、打字机锚定）都出在这层；每次验证靠手搓 CDP 探针，交接记录中两次被探针自身缺陷误导。`playwright-core` 已在 devDependencies 闲置未用。
- **建议**：正式搭 Playwright for Electron 冒烟，先覆盖三条最易回归链路：① 心流进入 + 打字机锚定（三种打字机配置 × 进出心流）；② `[[` 补全 + Alt+Enter 预览 + 普通 Enter 插入；③ 预览初始位置与双向同步。把「发版前手测清单」逐步固化为脚本。
- gitService 集成测试在 Windows 的超时问题已有既定口径（AGENTS.md），保持 `--testTimeout=90000` 即可。

## 五、明确不做的事

- 不换 UI 框架、不换编辑器内核、不上 Tauri——迁移成本远大于收益；
- **不引入 SQLite 或任何后端**：「纯文件 + git」是产品差异化根基；
- 不搞专门的「重构季」：小步快发的节奏是资产，§三全部随功能顺路做（童子军军规）。

## 六、建议落地顺序

1. **加固批次**（§二.1–7，约 1~2 天量级，改动都很小）：可随 v0.8.3 一并或紧随其后发一个补丁版；

3. **Playwright E2E 冒烟**：三条链路先行；
