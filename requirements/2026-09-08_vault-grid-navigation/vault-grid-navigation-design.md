# 笔记库卡片网格导航设计（v2 提案）

> 状态：**P1 + P2 已全部实施**（P1 随 v0.3.5 发布；P2 库卡片双列 + 强调色浅底随下版本发布。动画基础版在 P1 顺手完成；笔记数统计经评估决议不做） ｜ 起草：2026-09-08
> 前置讨论：项目所有者与开发代理关于「库卡片与笔记卡片易混淆」的讨论结论。
> 关联文档：[plugin-design.md](../2026-09-08_plugin-system/plugin-design.md)（同为 v2 系列提案）。

## 1. 背景与问题

现状：点击侧栏「笔记库」标题，主区域以卡片网格展示所有笔记库（名称 + 描述 + Git 状态），卡片仅有 ⋮ 菜单（重命名 / 删除），**无法打开查看库内容**。想看库里的笔记必须回侧栏展开树。

目标：双击库卡片进入该库，库内笔记与文件夹以卡片形式展示（带功能菜单）。

核心风险（讨论中确认）：用户面对眼前的卡片，需要反应才能判断「这是笔记库的卡片，还是库内容的笔记卡片」。

**设计立场：不把宝押在「卡片样式区分」单一手段上。** 用户识别卡片靠位置、图标、尺寸、色彩、上下文多线索叠加；样式区分只是其中一层，且不是最重要的那层。

## 2. 三层防线

### 第一层：上下文导航（最重要）

用户困惑的根本不是「卡片长得像」，而是**不知道自己在哪一层**。界面明确表达「你现在在哪」，即使卡片样式接近也不会误读：

| 机制 | 说明 |
| --- | --- |
| 面包屑 | 进入库后网格头部显示 `笔记库 / 工作笔记`，最左返回箭头可回退；进入子文件夹续为 `笔记库 / 工作笔记 / 项目资料`；点击任意一级回该级 |
| 标题联动 | 库列表页头部 = 「笔记库」+ 书本图标；进入库后 = 库名 + 文件夹图标。标题区永远描述「当前这屏是什么」 |
| 进入动画 | 双击时内容左滑出、新层级滑入（0.2s ease，与悬浮预览同款）。运动方向强化「钻进去 / 退出来」的空间心智 |
| 操作提示 | header 右侧提示文案：库列表页「双击打开笔记库」；库内容页「单击预览 · 双击编辑」（沿用现有模式） |

### 第二层：三种卡片的多维区分

「**尺寸 + 图标 + 色彩**」三管齐下，任一线索单独失效（色弱、深色主题）仍有冗余：

| | 笔记库卡片 | 文件夹卡片 | 笔记卡片 |
| --- | --- | --- | --- |
| 尺寸 | **占两列**（明显更大） | 单列，略矮 | 单列（现状） |
| 图标 | 大号文件夹（堆叠感，24px+） | 文件夹图标（常规） | 文档图标 |
| 色彩 | **强调色浅底**（`--accent-soft`）或左侧强调色竖条 | 中性底 | 中性底（现状） |
| 内容 | 描述 + 笔记数 + Git 状态 | 条目计数（「3 篇 · 2 个文件夹」） | 三行内容摘要 |
| 标题字号 | 15px 加粗 | 13px | 13px（现状） |

两个关键洞察：

1. **内容摘要是天然区分器**——三行灰字正文一出现即是笔记；库 / 文件夹卡片无摘要、靠计数填充，视觉密度天然不同；
2. **强调色底只用在库卡片**——最强快速识别信号，且与应用「高亮 = 当前」的语言一致；文件夹卡片保持中性，否则库内容页彩色一片反而失焦。

### 第三层：交互规则一致性

「双击 = 钻进去 / 打开，单击 = 轻量动作」的心智贯穿全部卡片：

| 卡片 | 单击 | 双击 | ⋮ 菜单 |
| --- | --- | --- | --- |
| 笔记库 | 无（或轻微高亮） | 进入库 | 重命名 / 删除（现状） |
| 文件夹 | 无 | 进入文件夹 | 重命名 / 删除 / **新建**（文件夹 / 笔记） |
| 笔记 | 悬浮预览（现状） | 进入编辑（现状） | 收藏 / 移出常用 / 删除（现状） |

文件夹菜单的「新建」顺带解决「网格视图内如何建笔记」的入口缺口（现状只能回侧栏树）。

## 3. 视图状态模型

`grid` 视图状态扩展（`stores/app.ts`）：

```ts
// 现状
{ name: 'grid'; section: 'recents' | 'favorites' | 'vaults' }
// 扩展：vaults 区携带钻入路径（空 = 库列表级）
{ name: 'grid'; section: 'vaults'; vaultPath?: string }
// vaultPath 形如 '工作笔记'（库级）或 '工作笔记/项目资料'（子文件夹级），POSIX 风格相对路径
```

- 面包屑由 `vaultPath` 拆解渲染；`vaultPath` 缺省 = 库列表级（现状行为不变）；
- 钻入 / 回退 = 修改 `vaultPath`；Esc 在内容级 = 回上级，在库列表级 = 关闭网格（现状行为）；
- 数据源：内容级调用现有 `tree:list` IPC 拿 `TreeNode[]`（侧栏树同源，folders 在前 notes 在后，按现有排序）；
- 文件夹卡片计数由 `TreeNode.children` 统计，无额外 IPC。

## 4. 动效规格

| 过渡 | 动画 |
| --- | --- |
| 钻入（双击库 / 文件夹） | 新层级自右滑入 + 旧层级左滑出（translateX ±48px，0.2s ease，与悬浮预览一致） |
| 回退（面包屑 / Esc） | 反向 |
| 库列表 ↔ 常用 / 收藏切换 | 无动画（现状，直接切换） |

实现提示：Vue `<Transition>` 包裹 grid-body，`vaultPath` 变化触发；方向由「变深还是变浅」决定。

## 5. 明确避免的坑

1. **不依赖单一区分手段**——尤其不只用颜色（主题切换、色觉障碍会抹平差异）；尺寸与图标是最稳的两条腿；
2. **不放「返回上级」卡片**（`..` 卡）——面包屑已承担回退，多一张卡片反而增加「这是不是文件夹」的判断成本；
3. **不给库卡片加「进入」按钮**——双击 + 提示文案足够，按钮会让卡片操作区拥挤且与 ⋮ 菜单抢注意。

## 6. 实施拆分（两步走）

导航骨架不通，样式再好也无意义，故：

- **P1 导航骨架**：`vaultPath` 状态 + 双击钻入 / 面包屑 / 返回 / Esc 规则 + 文件夹卡片（基础样式：图标 + 名称 + 计数）+ 内容级数据接入（`tree:list`）+ 文件夹菜单「新建」；
- **P2 样式与动效**：库卡片双列 + 强调色浅底、钻入 / 回退滑动动画、库卡片笔记数统计（需要 `vault:list` 带计数或懒统计——实现时评估）、header 提示文案分级。

验收要点（P1 完成即可手动验证）：

- 双击库卡片 → 看到库内文件夹 + 笔记卡片，面包屑正确；逐级进入子文件夹路径正确；
- 面包屑点任意一级、Esc 逐级回退、库列表级 Esc 关闭网格，行为符合预期；
- 在库内容级新建笔记 / 文件夹成功后卡片即时出现；
- 回收站 / 常用 / 收藏视图不受影响；
- 「当前视图高亮」在钻入后仍正确（侧栏「笔记库」标题保持高亮）。

## 7. 待确认项

1. **库卡片笔记数**：显示总量需要遍历统计（大库可能慢），可选「懒统计 + 缓存」或首版不显示——倾向首版不显示，P2 评估；
2. **空文件夹展示**：计数为 0 时显示「空文件夹」字样还是留白——倾向留白（与笔记无摘要时一致）；
3. **网格 / 列表切换**（规划中功能）落地时，钻入导航对两种形态均需生效——本设计的面包屑与交互规则与形态无关，可直接复用。
