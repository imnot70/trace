# 草稿笔记 — 技术设计

> FR-2.3.9，2026-09-26。分支：待建（建议 `feat/draft-notes`，基于 main v0.8.7+）。

## 1. 架构：伪笔记库（v2 方案，用户定稿）

草稿是**真实文件**，存放在应用数据目录 `userData/scratch/`，以一个**内部伪库**接入现有文件体系：

- 伪库 vault 常量：`SCRATCH_VAULT = '__scratch__'`（用户库命名校验不允许该形态，不会冲突）；
- 文件 IPC 入口按 vault 特例解析：`readNote` / `saveNote` / `deleteNote` / `fsTree.list` / `createNote` 判断 `vault === SCRATCH_VAULT` → 路径解析到 `userData/scratch/`（不走工作区 resolveWithin，改走 scratch 目录内的等价校验）；
- 图片资产：`userData/scratch/assets/`，`trace-vault://` 协议对 scratch 库同样特例（FR-2.5 管线复用）。

**v2 相对初版（内存缓冲区）的决定性优势**：内容被自动保存（1s 防抖）持续写入真实文件，「未落盘」状态不存在——崩溃安全、天然支持多份草稿；大部分子系统因「scratch 不在工作区」**自动获得正确行为**（见 §2），无需逐一容错。

## 2. 自动排除范围（特性，非缺陷）

草稿不在工作区，因此以下子系统**天然不涉及**，无需代码：

| 子系统 | 行为 | 语义 |
| --- | --- | --- |
| 全局搜索 | 索引只扫工作区库 | 草稿不可搜（临时想法不污染搜索） |
| 双链 / 反向链接索引 | 同上 | 草稿中的 `[[引用]]` 不算数 |
| 标签索引 | 同上 | 草稿 frontmatter 的 tags 不进标签体系 |
| Git 同步 / 自动同步 | scratch 非 git 仓库 | 草稿永不同步；转正后才进入同步体系 |
| 回收站 | 草稿删除为永久删除 | 「临时」语义 |

需要**显式处理**的守卫（guard 清单）：

| # | 位置 | 处理 |
| --- | --- | --- |
| G1 | `fs:saveNote` / `fs:readNote` / 删除 / 列表 IPC | vault 特例解析到 scratch 目录 |
| G2 | editor store `addRecent` | scratch 笔记跳过（转正后路径变更，避免常用列表失效） |
| G3 | 收藏入口 | scratch 笔记不显示收藏（转正后可用） |
| G4 | `Ctrl+S` / 保存按钮 | 草稿态拦截 → 转正对话框（不发常规保存 IPC） |
| G5 | 粘贴 / 拖入图片 | 写入 `scratch/assets/` 而非库附件目录 |

## 3. 交互设计

### 3.1 创建（Ctrl+N）

- 当前为草稿且内容 trim 后为空 → 聚焦该草稿（不生成空文件）；
- 否则创建 `速记 MMDD-HHmm.md`（重名追加序号 `-2`、`-3`）并打开、自动聚焦。

### 3.2 侧栏「草稿」菜单

- 位置：左侧栏「常用」下方；**草稿存在时才显示**（不打扰空态）；
- 列表：草稿名（去扩展名）+ 相对时间，点击打开（editor.openNote 到 scratch 伪库）；
- ⋮ 菜单：转正为笔记 / 删除（红字，永久删除 + 确认）。

### 3.3 转正（Ctrl+S / 保存按钮 / 侧栏 ⋮「转正为笔记」）

对话框（复用 `MoveDialog` 树形选择器组件）：

1. 目标库（下拉，现有库列表）+ 目录（树形选择，默认 = 当前位置上下文）+ 笔记名（默认去掉草稿名的时间戳，可改，重名校验）；
2. 确认后：`createNote(vault, dir, name, content)` 建正式笔记 → 若 `scratch/assets/` 有该草稿引用的图片：复制进目标库 `attachmentsDir` 并**改写引用路径前缀**（`assets/` → `attachmentsDir/`）→ 删除 scratch 草稿文件与已迁资产；
3. `editor.current` 切换到正式路径 → `addRecent` 开始正常记录 → 提示「已转正」。

心流模式下转正对话框以浮层呈现（与浮层侧栏同思路）。

### 3.4 顶栏 / 状态区

- 顶栏保存按钮：草稿态 title 变为「转正为笔记 (Ctrl+S)」；
- 心流右下角状态区：草稿态保存圆点语义不变（未保存淡显——自动保存到 scratch 也算「已保存」，圆点静置）。

## 5. 决策记录

- **D1 架构 = 真实文件伪库**（用户方案，2026-09-26 定稿）：替代初版内存缓冲区——自动保存持续落盘消灭「未落盘丢失」，多份草稿天然支持，子系统自动排除（对照表见 §2）；难度由 ★★★ 降至 ★★☆。
- **D2 菜单名 = 「草稿」**（候选：速记 / 暂存）。
- **D3 草稿贴图 = 方案 a**：图片进 `scratch/assets/`、转正随迁改写（快速记录时贴图常见）。
- **D4 Ctrl+N 空草稿复用**，非空才新建。
- **D5 草稿删除 = 永久删除**（红色确认），不进回收站。

## 6. 工时

★★☆，约 **2~2.5 天**（伪库特例 + 侧栏菜单 + 转正对话框 + 图片随迁 + 守卫 + 单测）。
