# 心流模式（Flow Mode）需求

> 创建：2026-09-23 ｜ 状态：**需求已确认（讨论稿），待技术设计**
> 关联：FR-2.4.13（所见即所得）、FR-2.9.5（专注模式）、FR-2.9.6（悬浮预览）
> 本文档记录需求结论（做什么、为什么）；技术方案见 [flow-mode_design.md](flow-mode_design.md)。

## 1. 背景与目标

### 1.1 背景

Typora 的打字机模式（光标固定、文字流动）带来很好的写作手感，但只提供「光标垂直居中」一种形态。本项目希望更进一步：

- **打字机模式分高位 / 低位**：高位 = 光标垂直居中（Typora 形态）；低位 = 光标锚定在编辑区偏下位置，回车后已有内容上移、光标位置不变——刚写下的内容始终停留在光标上方，视线无需移动。
- **一个专为创作设计的沉浸形态**：进入后自动隐藏无关界面、自动切所见即所得、自动开启打字机，让「写」这件事本身变得愉悦。

### 1.2 目标

做一个让人更愉悦、更沉浸的创作形态，且**不破坏项目的初心**：Trace 仍是一个简单的、能通过 git 同步日记的笔记工具——文件始终是纯 Markdown，模式只是呈现层。

### 1.3 关键设计约束：不制造模式混乱

现有模式已经存在多条轴，若心流模式做成「第四个互斥模式」，会立即出现组合爆炸（心流里算什么编辑形态？心流和专注是什么关系？）。因此本需求确立核心模型：

> **三条正交轴 + 一个一键预设**。心流模式是「把各轴拨到位」的预设，不是新的模式枚举值。

| 轴 | 取值 | 现状 | 回答的问题 |
| --- | --- | --- | --- |
| 编辑形态 | 源码 / 所见即所得 | 已有（Ctrl+E） | 内容怎么呈现 |
| 环境强度 | 常规 / 专注 | 已有（Alt+F） | 界面露多少 |
| 光标锚定 | 关 / 高位 / 低位 | **本需求新增** | 光标钉在哪 |

心流模式 = 预设（所见即所得 + 专注 + 打字机 + 写作栏宽 + 音效 + 保存指示），一键进入，进入后每条轴仍可单独调整。

## 2. 决策记录（2026-09-23 讨论确认）

| # | 决策点 | 结论 | 理由 |
| --- | --- | --- | --- |
| D1 | 心流模式的定位 | **预设（preset），不是第四个模式** | 三条正交轴保持独立，心流只是「一键拨到位」；避免组合爆炸与心智负担（见 1.3） |
| D2 | 命名与入口 | 命名「**心流模式**」，快捷键 **Alt+W**（W = Write，现无冲突），编辑卡顶栏提供按钮 | 「心流」是现成的创作心理学概念，与「专注」形成清晰递进（专注=藏干扰，心流=进状态），不被误读为一种编辑格式 |
| D3 | 打字机独立成轴 | 打字机模式是独立设置项（关 / 高位 / 低位），**源码模式下也可用** | 它本来就与其他轴正交；独立后 P1 即可单独交付，不必等心流预设齐活 |
| D4 | 低位锚点位置 | 默认锚定在**距底边约 20%** 处（不贴边），锚点比例内部可调 | 贴底有三个问题：中文输入法候选框无下落空间（挤压/抖动）、视觉压迫、刚写内容离视线过近 |
| D5 | 打字机滚动策略 | **仅在实际输入与光标移动时重锚；用户滚动查看前文时绝不干预**（滚动后下一次输入才回到锚点） | 强制弹回会让人想砸键盘；这是打字机模式的生死线 |
| D6 | 音效实现 | **Web Audio 程序合成**（无音频文件、零体积、无版权），默认关闭、仅回车触发、带限流与音量 | 合成「thock」音质可接受且可调音色；随包音频素材有版权与体积成本 |
| D7 | 音效作用范围 | 音效开关是持久化设置项，但**只在心流模式内生效** | 收窄打扰半径，同时强化「进入心流 = 进入创作状态」的仪式感 |
| D8 | 退出语义 | **Esc 一键退出，无确认弹窗**；退出恢复进入前的界面状态；下次进入沿用上次的心流偏好 | 沉浸模式不能锁死用户；恢复外部状态与记忆心流偏好是两件事，需分别定义（见 FR-F2） |
| D9 | 写作栏宽 | 心流模式内默认启用行宽限制（约 42 字符），设置项可调三档 | 宽屏下全宽长行阅读疲劳，是沉浸感与可读性的低成本高收益项 |
| D10 | 保存信任 | 心流模式内提供**极微弱的保存指示**（打字时淡出、保存成功微脉冲、失败红色） | 第一原则「不悄悄丢数据」：沉浸模式藏起了未保存圆点与同步状态，必须有替代品 |
| D11 | 落地节奏 | 分三期：P1 打字机 → P2 心流预设（含栏宽、保存指示）→ P3 音效；均独立可发版、可回退 | 每步单独闭环，符合「简单工具」底色 |

## 3. 功能需求

### FR-F1 打字机模式（独立设置项）

**设置项**：设置 → 编辑器 →「打字机模式」：`关闭 / 高位 / 低位`（默认关闭）。

- **高位**：光标所在行始终保持在编辑区垂直居中（50%）；
- **低位**：光标所在行锚定在编辑区偏下位置（默认约 80% 高度，即距底边 20%）；
- 两种模式下，**输入导致的滚动表现为「文字移动、光标不动」**；
- 生效范围：源码模式与所见即所得模式均可用；编辑卡顶栏提供快捷切换入口（可后续加）。

**行为规则**（详细对照表见设计文档）：

- 输入字符 / 回车 / 删除、撤销重做、键盘移动光标、鼠标点击定位 → 重新锚定；
- 用户滚动查看前文（滚轮 / 滚动条）→ **不干预**，下一次输入时回到锚点；
- 鼠标拖选过程中不重锚（拖选结束再锚定），避免连续滚动造成眩晕；
- 中文输入法组词期间不重锚（组词确认后锚定），避免候选框抖动。

**与既有能力的关系**：

- 与预览联动是白送的：编辑器滚动会触发现有行级双向滚动同步，预览自动跟随（无需新增逻辑）；
- 文档不足一屏时同样成立（靠留白把锚点位置撑出来，见设计）。

### FR-F2 心流模式（一键预设）

**进入**：编辑卡顶栏「心流」按钮，或快捷键 **Alt+W**。进入时自动：

1. 隐藏左侧栏（同专注模式，含迷你导航条）；
2. 隐藏顶栏与格式工具栏（复用「专注隐藏顶栏」行为，鼠标移至编辑卡顶部可整体唤出）；
3. 切换到所见即所得编辑形态；
4. 开启打字机模式（形态取心流偏好，默认低位）；
5. 启用写作栏宽限制（FR-F3）；
6. 启用保存指示（FR-F5）；
7. 若心流音效已开启，回车时播放音效（FR-F4）。

**退出**：`Esc` 一键退出（无确认弹窗）；再次按 Alt+W 同样退出。

**状态语义**（两类状态分开定义）：

| 类别 | 内容 | 退出心流 | 下次进入心流 |
| --- | --- | --- | --- |
| 外部界面状态 | 侧栏可见性、专注模式、预览分栏、编辑形态 | **恢复进入前状态** | — |
| 心流偏好 | 打字机形态、音效开关与音量、栏宽档位 | 不改变 | **沿用上次** |

**不锁死用户**：

- 心流模式内每条轴仍可单独调整（如 Alt+B 唤出侧栏、Ctrl+E 切回源码），退出时按上表恢复；
- 保留快速跳转能力：Ctrl+F 全局搜索、Ctrl+N 新建笔记在心流模式内照常可用（写日记常需翻看前一篇）。

### FR-F3 写作栏宽

- 心流模式内正文列宽限制在舒适阅读宽度（默认约 42 字符、居中对齐）；
- 设置 → 编辑器提供三档：窄（约 32 字符）/ 中（约 42 字符）/ 宽（约 52 字符）；
- 仅作用于编辑区文本列，不影响侧栏、预览卡与窗口布局。

### FR-F4 回车音效

- **触发**：仅回车（含列表自动续行等换行插入）触发；打字、删除等其他输入不发声；
- **音色**：程序合成的机械「thock」质感（短噪声脉冲 + 低通 + 指数衰减 + 低频木质分量），每次触发带轻微随机变化避免机械重复感；
- **默认关闭**：设置 → 编辑器 →「心流音效」开关（默认关）+ 音量滑杆（默认 60%）；
- **限流**：连续回车最小间隔约 120ms，超出窗口不叠加播放；
- **范围**：仅心流模式内生效（D7）。

### FR-F5 保存信任（心流模式内的保存指示）

- 心流模式内于编辑区右下角显示一个**极微弱的保存状态指示**（默认几乎不可见）：
  - 输入中 / 有未保存变更：淡入为微弱圆点；
  - 保存成功：一次轻微脉冲后淡出；
  - 保存失败 / 外部修改冲突：转为红色常亮（同时保留既有的 ElMessage 提示）。
- 不占布局、不打断输入、不显示文字（只有颜色与动画）。

### FR-F6 设置与快捷键登记

- 设置 → 编辑器新增：打字机模式（关 / 高位 / 低位）、写作栏宽（三档）、心流音效（开关 + 音量）；
- 快捷键表（`config/shortcuts.ts`）登记 `Alt + W`；`Esc` 的分级回退链扩展为：
  「关闭悬浮预览 → **退出心流模式** → 返回上级文件夹 → 关闭网格」。

## 4. 非目标（首版不做）

- **环境音**（雨声 / 咖啡馆 / 壁炉）——需音频素材与独立面板，留待 P4 评估；
- **写作统计 HUD**（今日字数、写作时长）——同上；
- **光标视觉动效**（平滑移动、光晕）——与滚动逻辑解耦后再评估；
- 改动常规模式 / 专注模式的既有行为；
- 单篇笔记的心流偏好记忆（全局一份配置）；
- 引入任何私有格式或非 Markdown 存储。

## 5. 验收标准

1. 打字机模式高/低位在源码与所见即所得两种编辑形态下均正确生效（文字流动、光标位置不动）；
2. 用户滚动查看前文不被强制弹回；下一次输入时回到锚点位置；
3. 中文输入法组词期间不发生抖动或跳动；组词确认后正确锚定；
4. 鼠标拖选过程中不连续滚动，拖选结束后正常锚定；
5. Alt+W 进入心流：侧栏与顶栏隐藏、编辑形态切为所见即所得、打字机生效、栏宽生效、保存指示出现；
6. Esc 一键退出（无弹窗），界面恢复到进入前状态；再次进入沿用上次心流偏好；
7. 心流模式内 Ctrl+F 搜索、Ctrl+N 新建、Alt+B 呼出侧栏均可用；
8. 音效默认关闭；开启后仅回车发声、限流有效、音量可调；关闭后无残留音频上下文；
9. 心流模式内保存成功 / 失败均有指示反馈，且不干扰输入；磁盘产物与常规模式完全一致（纯 Markdown，无格式漂移）；
10. 关闭打字机模式后，编辑器滚动行为与现状完全一致（无残留 padding / 监听）；
11. 既有单元测试不回归；锚点计算与音效限流逻辑有单元测试覆盖。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 音效从「愉悦」变「打扰」（开会、戴耳机、深夜） | 默认关闭；仅回车触发；仅心流模式内生效；限流 + 音量可调（D6/D7） |
| 打字机滚动与既有滚动同步互相干扰（回环、抖动） | 复用现有 100ms 防回环守卫；仅在输入/光标事件重锚，程序化写入不触发（设计文档规则表） |
| 中文输入法组词期滚动导致候选框错位 | 组词期间冻结（复用所见即所得已验证的 `view.composing` 冻结经验） |
| 模式继续增殖，用户心智负担上升 | 本次确立「三轴 + 预设」模型并写入文档；未来新形态一律作为轴向取值或预设，不新增模式枚举（1.3） |
| 低频输入下滚动生硬、高频输入下掉帧 | 滚动经 requestAnimationFrame 合并，每次输入至多滚动一次；首版即纳入性能验收 |
| 沉浸模式隐藏了保存状态，用户信任感下降 | 保存指示（FR-F5）；保存失败仍然弹提示（既有行为不变） |
