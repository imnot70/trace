# 所见即所得渲染修正（Live Preview Render Fix）需求

> 创建：2026-09-24 ｜ 状态：**已实施（待发版）**——实施记录与实测数据见 [live-preview-render-fix_design.md](live-preview-render-fix_design.md) 第 8 节
> 关联：FR-2.4.13（所见即所得编辑模式）——本次为其**实现缺陷修复**，不新增 FR 编号
> 本文档记录缺陷现象与验收标准；根因、方案与技术细节见 [live-preview-render-fix_design.md](live-preview-render-fix_design.md)。

## 1. 背景

所见即所得（Live Preview）模式下，用户实测（2026-09-24，4 张截图）发现两类呈现缺陷：

1. **行号与正文错位**：笔记含块级公式时，公式之后的正文行「行号 / 行号高亮」与正文行不在同一水平线上——高亮行的行号跑到别处（截图 1）；
2. **列表 / 引用 / 任务列表未按渲染形态呈现**（截图 2、3）：`-` 原样可见、任务复选框不可见（但 `[ ]` 已被吞掉，导致该行显示成 `- 未完成任务`）、引用的 `>` 未隐藏。

两者都直接削弱该模式的价值：前者让「当前行」定位失真（行号高亮是用户判断光标的锚点），后者使「渲染态」与源码态几乎无法区分，用户会怀疑模式是否真的生效。

## 2. 缺陷 1：行号 / 行号高亮与正文错位

### 2.1 现象

含块级公式（`$$…$$`）的笔记中，块级公式**之后**的所有行，其行号相对正文行整体上移；上移量随上方块级 widget（公式块 / 表格 / HTML 块 / 水平线）的数量与高度累加。第 18、19 行尤为明显（截图 1 中「18」的高亮位置与正文的空白行对齐，而正文文字落在「19」的位置上）。

### 2.2 本机复现与量化（2026-09-24，隔离实例实测）

复现文档：正文 + 一个多行块级公式 + 表格，切换到所见即所得后测量行号列与正文行的 `getBoundingClientRect().top`：

| 位置 | 行号列 y | 正文行 y | 偏差 |
| --- | --- | --- | --- |
| 公式块之前的行（1–18） | 与正文一致 | 与正文一致 | 0 |
| 公式块之后第一行（第 22 行） | 716 | 731 | **15px** |
| 表格之后（第 28 行） | 989 | 1016 | **27px** |

即：每个块级 widget 都会引入一段固定偏差，且**逐块累加**（公式块 +15、表格再 +12）。

### 2.3 期望

- 任意块级 widget（块级公式 / 表格 / 内嵌 HTML 块 / 水平线 / frontmatter 折叠）之后的**任何行**，其行号与行号高亮与正文行严格对齐（允许 ≤1px 的亚像素误差）；
- 该性质与滚动位置、文档内容无关（不因 widget 高度、数量变化而漂移）；
- 顺带收益：依赖行高映射的能力（预览行级同步滚动、跳转到指定行）不再有累积偏移。

### 2.4 复现期间附带发现的既有缺陷（一并修复）

**文档以 frontmatter 开头时，所见即所得几乎完全失效**：只要笔记带 frontmatter（标签即存于此），进入所见即所得后**只有块级公式还能渲染**——标题、列表、引用、表格、行内样式全部退回源码。根因为两处装饰计算的 frontmatter 剪枝写成了「区间相交」判定，`Document` 根节点必然与 frontmatter 相交，导致语法树在根节点被整棵剪掉（详见设计文档 §2.1 与 §7）。因该缺陷对「带标签的笔记」100% 复现，属可用性级别问题，与本次缺陷 1 / 2 一并修复。

## 3. 缺陷 2：列表 / 引用 / 任务列表的渲染

| 语法 | 现状（实测） | 期望 |
| --- | --- | --- |
| `- 普通列表项` | `-` 原样可见（`- 普通列表项一`） | 标记渲染为「•」（次级色），文本紧随其后 |
| `1. 有序列表项` | 与期望一致（保留编号） | 保留源编号（与主流编辑器一致） |
| `- [ ] 待办` / `- [x] 已办` | `-` 可见、`[ ]` 被隐藏但**复选框不可见**（显示为 `- 未完成任务`：标记在、方框空） | 复选框正常渲染（未勾选 / 已勾选两种形态），点击可切换勾选；`- ` 不再显示 |
| `> 引用内容` | `>` 原样可见 | `>` 与其后一个空格隐藏；保留左侧引用条与缩进 |

**光标行回落（既有原则不变）**：光标所在行仍回落为源码形态（`- [ ] 文本` 完整可见），移开该行后重新渲染。本次将三处标记的回落判定统一为「**该行被光标占用即整行回落**」（详见设计文档 D2）。

### 3.1 行内标记的露出粒度（2026-09-24 追加，用户选定方案 B）

用户实测反馈：光标停在 `~~删除~~` 的**内容末尾**时，两端 `~~` 与删除线同时可见，看着像「删除线下面挂了两条波浪号」。经确认采用更细的粒度——**行内标记（加粗 / 斜体 / 删除线 / 行内码）只在真的贴到定界符时才露出源码**：

| 光标 / 选区位置 | 期望 |
| --- | --- |
| 内容里（中间、两端，含正在输入时） | **保持渲染**（不显示 `~~` / `**` / 反引号） |
| 紧贴定界符外侧（打开标记之前 / 闭合标记之后） | 露出源码 |
| 定界符内部（多字符标记的字符之间，如 `~~` 两字之间） | 露出源码 |
| 选中定界符（选区与标记重叠） | 露出源码 |

约束：定界符必须始终**可编辑**（方向键能进入、能选中、能删除）；链接 / 双链 / 图片 / 公式等 widget 与块级结构沿用原有「光标进入即回落源码」的规则——它们的隐藏部分是 URL 或整块内容，需要「点一下就回落」以便编辑。

## 4. 非目标

- 不改动右侧预览、导出 PDF / HTML 的渲染结果；
- 不做表格可视化编辑、软换行、块拖拽等所见即所得的其它增强；
- 不改变「文件始终是纯 Markdown、所见即所得只是呈现层」的既有前提（FR-2.4.13）；
- 不改动代码块 / 公式的既有呈现规则。

## 5. 验收标准

1. 含「块级公式 + 表格 + 水平线」的笔记，任意滚动位置下：行号列、行号高亮、正文行三者的垂直位置一致（≤1px）；连续插入 / 删除块级 widget 后依然成立；
2. 无序列表标记呈「•」、文本对齐正常（含嵌套列表缩进）；
3. 任务列表显示为复选框，勾选 / 取消勾选写回源码 `[x]` / `[ ]` 并触发自动保存；
4. 引用行不再显示 `>`，左侧引用条保留，多行引用每行都生效；
5. 光标进入上述任一行时，该行回落为源码形态；移开后重新渲染；
6. 中文输入法组词期间不出现抖动（复用既有 IME 冻结策略，不因新增装饰而回归）；
7. 既有单元测试全部通过，并新增标记装饰与回落规则的单元测试（覆盖无序 / 有序 / 任务 / 引用四类）；
8. 磁盘产物不变（仍是纯 Markdown，无任何格式改写）。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 隐藏 `>` / `-` 后，用户难以判断「这是一段引用 / 列表」 | 保留引用条与缩进等视觉线索（渲染态本就有这些线索）；光标移入即回落源码，随时可确认语法 |
| 标记隐藏范围写错会破坏正文（例如把列表项首行的文字一并隐藏） | 只替换语法树给出的标记节点区间；新增单测逐类断言区间与内容不受影响 |
| 块级 widget 的高度修正若引入额外空白，会改变既有观感 | 采用的方案保持视觉间距**数值不变**（只把「不被测量的外边距」换成「被测量的等量内边距」），并以实测对齐数据验收 |
| 新增装饰与 IME / 光标回落交互回归 | 复用既有 `occupied()` 判定与组词冻结路径；真机（CDP + 输入法组词）复验 |
